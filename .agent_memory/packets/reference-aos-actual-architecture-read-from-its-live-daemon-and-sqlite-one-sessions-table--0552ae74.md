# AO's actual architecture, read from its live daemon and SQLite: one sessions table, orchestrator and worker are the same object

> Agent Orchestrator v0.12.5 was studied live on 2026 08 20 through its own surfaces — its daemon serves a JSON API on …

Agent Orchestrator (v0.12.5) was studied live on 2026-08-20 through its own surfaces — its daemon serves a JSON API on localhost:3001 under /api/v1 (projects, sessions, notifications, agents, settings, and an SSE /api/v1/events change feed), and its state lives in ~/.ao/data/ao.db (SQLite). The findings that matter for Kage's orchestrator design: (1) There is ONE `sessions` table; the orchestrator is just a row with kind='orchestrator' beside kind='worker' rows — same lifecycle, same viewer, same machinery, orchestrator branch ao/<project>-orchestrator, workers ao/<project>-N/root. (2) Every session has session_mode 'tui' (a live terminal you watch and type into) or 'chat' — two VIEWS of one session concept, never two different managers. (3) Sessions record agent_session_id AND native_transcript_path — chat rendering is parsed from the harness's own native transcript, which is how chat and terminal stay one source of truth. (4) activity_state is exactly ('active','idle','waiting_input','blocked','exited') — waiting_input vs blocked is a schema-level distinction. (5) Cards render instantly from denormalized latest_user_prompt / latest_assistant_update columns on the session row. (6) Loop-closing flags per session: auto_inject_review and auto_inject_ci (PR review comments and CI failures are injected back into the session automatically), reviewer_harness, terminate_on_pr_merge, is_pinned, preview_url. (7) Every mutation writes to a change_log table via triggers — their SSE feed is CDC, like Kage's notify-only feed. (8) 27 harnesses in the harness CHECK constraint. What AO does NOT have: any verification of worker claims, any memory, any brief compilation — sessions are wrapped, never briefed or checked.
Evidence: curl http://localhost:3001/api/v1/projects|sessions|agents|settings|events returned live data (sessions listed kind/mode/activity/branch per session); sqlite3 ~/.ao/data/ao.db .schema for sessions, session_worktrees, shell_terminals read directly; ~/.ao/running.json names pid 49298 port 3001; app-state.json names v0.12.5.
Verified by: Direct reads of AO's live API and SQLite schema on this machine, 2026-08-20
