# shell/main.js's projectDir was a top-level `const` computed at module-eval time; since ...

> shell/main.js's projectDir was a top level const computed at module eval time; since resolving it now needs app.getPa…

shell/main.js's projectDir was a top-level `const` computed at module-eval time; since resolving it now needs app.getPath('userData') (for the remembered-project fallback), it had to become a `let` assigned inside app.whenReady(), matching how windowStatePath()/savedWindowState() already defer app.getPath() calls until after ready.

Learned while delivering: Fix the packaged desktop app failing to launch from Finder/Spotlight with: Kage could not start. env: node: No such file or directory. All changes are in shell/main.js. Root cause has two stacked parts. (1) PROJECT DIR: projectDir falls back to process.cwd(), which is / for a Finder-launched app, so existingDaemonUrl() reads /.agent_memory/daemon/status.json, finds nothing, and never discovers the healthy daemon already running for the real project. Fix: persist the last successfully loaded project dir to a JSON file in app.getPath(userData) (pattern already in this file: windowStatePath/savedWindowState) every time openAppInWindow successfully loads a daemon URL; on launch, resolve projectDir as --project arg, then KAGE_PROJECT env, then the remembered last project (validate the dir still exists), and treat a cwd of / as no-cwd rather than a project. If nothing is known, show the splash error explaining plainly: open Kage once from a terminal with kage app, or launch with open -a Kage --args --project <dir>. (2) PATH: resolveCli() finds the global kage binary THROUGH a login shell precisely because Finder apps inherit almost no PATH, but ensureDaemon() then execFiles that binary WITHOUT the login shell PATH, so the script shebang #!/usr/bin/env node fails with env: node: No such file or directory. Fix: capture the login shell PATH once (SHELL -lic echo $PATH, with a fallback to the current PATH on failure) and pass it in the env of the ensureDaemon execFile; keep ELECTRON_RUN_AS_NODE=1 exactly as-is for the viaNode dev-checkout case. Do not change the daemon, the API, or any behavior when launched from a terminal with a proper PATH and cwd. Keep the file dependency-free and zero-HTML per its header contract. Verify shell/main.js still parses with node --check. Success = npm test fully green (the mcp suite must not regress) and node --check shell/main.js exits 0.
Verified by: npm test --prefix mcp, diff-size, citations
