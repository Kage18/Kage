# The five sub-mutation-classes 'qtime', 'pnl-tl-at', the memory-panel's 'label' class, a...

> The five sub mutation classes 'qtime', 'pnl tl at', the memory panel's 'label' class, and the bare ticker SPANs are N…

The five sub-mutation-classes 'qtime', 'pnl-tl-at', the memory-panel's 'label' class, and the bare ticker SPANs are NOT five separate code paths — every one of them is created via the single ageSpan(cls, iso, prefix, suffix) helper (app-client.ts:117), which sets a data-age attribute; all of them are patched by the ONE tickAges() sweep over document.querySelectorAll('[data-age]') (app-client.ts:147). Gating tickAges' single write site with writeIfChanged silences all five mutation classes at once — the 'six mutation sources' in the brief collapse to exactly two code paths (tickAges, and renderProjects' plist/sidefoot rebuild).

Learned while delivering: Write-if-changed: finish the render calm to AO-at-rest zero. Measured on the live app just now with a MutationObserver over 8 seconds at rest (nothing running, no data changing): childList:SPAN 202 mutations (~25/s) - the age ticker rewrites every age label's text node each second even when the rendered string is IDENTICAL ('17h' -> '17h'); plus plist 9 (~1/s, the sidebar project list rewriting on its poll), label 14, qtime 9, pnl-tl-at 4, sidefoot 4. Section render counts were ZERO over the same window - the revision gating from the just-merged render-calm run works; this is the last mile.

THE FIX, in mcp/delegation/app-client.ts: every periodic text patch becomes write-if-changed - compute the next string, compare against the node's current textContent, and skip the write when equal (the ticker, the qtime/pnl-tl-at/sidefoot/label updaters, and the plist poll's row updates - find each of the six mutation sources named above and gate it; name each site in your claim). Prefer nodeValue on the text node over textContent replacement where a text node already exists, so an actual change is characterData, not childList churn. No behaviour change when strings differ - ages still tick the second they change.

ACCEPTANCE: extend mcp/render-calm.test.ts (this feature's own test file - editing it is in scope for exactly this) with: the extracted write-if-changed helper skips the write on equal strings and writes on differing ones; the ticker path uses it (assert via the page string that the helper name appears in the ticker's code path). State in your claim the expected at-rest mutation rate after the change (should be ~0 when no age string rolls over).
