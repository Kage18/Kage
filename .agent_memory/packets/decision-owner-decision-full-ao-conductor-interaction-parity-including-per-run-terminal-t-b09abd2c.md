# Owner decision: full AO + Conductor interaction parity — including per-run terminal take-over, reversing the no-per-run-PTY cut

> Owner directive 2026 08 18 : Kage must carry BOTH competitors' mid run interaction models, not a curated subset. Cond…

Owner directive (2026-08-18): Kage must carry BOTH competitors' mid-run interaction models, not a curated subset. Conductor's structured layer: the queue as a first-class object (edit/reorder/delete queued messages, drafts preserved) on top of per-message delivered flags in steer.jsonl; an explicit steer-now vs queue-for-idle choice with a modifier sending the opposite (immediate stays the default — Conductor shipped queue-by-default and reverted within one release); true interrupt (session alive) surfaced from the existing control_request path. AO's raw-access layer: per-run terminal take-over — an interactive claude --resume of the run's session in its worktree through the existing pty machinery, with honest state transitions (supervisor detaches; the run is marked taken over; a later tell re-supervises). This REVERSES the original delegation plan's deferred-list entry "Raw PTY/terminal attach (explicitly cut — timeline only)": the cut applied to runs, the Room already got a pty, and the owner now wants run-level attach too. Kage's differentiator on top of both models stays the honest delivery vocabulary and the verification loop the interactions feed. Build order (tasks #77-80): kernel delivered-flag substrate first — queue editing cannot be honest on an append-only log — then queue UI + delivery choice, then interrupt surfacing, then take-over.
Evidence: Owner in session: "we need to have both what AO and Conductor has", following the steer-model comparison (AO attach-and-type vs Conductor structured queue/approvals).
Verified by: Owner instruction, 2026-08-18.
