> mcp/delegation/app client.ts's tokenizeText function new in this reference diff, absent at the merge base had two und…

mcp/delegation/app-client.ts's tokenizeText() function (new in this reference diff, absent at the merge-base) had two under-escaped backslashes in its delims array (\n and \") beyond the one bug named in the brief — same failure class as split("\n\n"). When fixing one flagged escape bug in this file, grep the whole file for (?<!\\)\\[ntr"'] rather than just the reported line, since sibling defects can ride in on the same diff.

Learned while delivering: Land the Room chat rendering fix, third attempt — the remaining defect is ONE under-escaped line. A content-complete implementation exists on branch kage/land-the-room-chat-rendering-fix-a-verif-260817-13cb; replicate it into this worktree with git show, byte-for-byte, EXCEPT for exactly one correction in mcp/delegation/app-client.ts: its line 448 reads: var paras = String(text || "").split("\n\n").filter(function (p) { return p.length > 0; }); — written with SINGLE backslashes, which inside this TS template literal compiles to a REAL newline inside the client string and kills the whole script at parse time (node --check on the composed page reports Invalid or unexpected token at that split). The correction: the backslashes must be DOUBLED in the TS source so the browser sees backslash-n — i.e. the split argument in the .ts source must be written with double backslashes before each n, exactly like the existing d.diffText.split with doubled escapes elsewhere in the same file. After replicating, scan your whole diff for any OTHER single-backslash escape inside client string literals (the file convention: every escape the BROWSER should see must be doubled in the TS source; grep your added lines for split/join/indexOf calls with backslash arguments and verify each is doubled). Change nothing else relative to the reference branch — the innerHTML gate wording from that branch is already correct. Success = npm test fully green, which includes the parse gate on the composed page.
