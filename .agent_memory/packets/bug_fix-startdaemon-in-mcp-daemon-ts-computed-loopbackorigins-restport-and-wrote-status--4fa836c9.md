# startDaemon in mcp/daemon.ts computed loopbackOrigins(restPort) and wrote status.json's...

> startDaemon in mcp/daemon.ts computed loopbackOrigins restPort and wrote status.json's rest port from the REQUESTED p…

startDaemon in mcp/daemon.ts computed loopbackOrigins(restPort) and wrote status.json's rest_port from the REQUESTED port before server.listen() ever ran — with --port 0 that would have wedged the guard and status file on port 0 forever. Fix: make restPort a `let`, reassign it from server.address() inside the listen() success callback, and rewrite status.rest_port + guardContext.allowedOrigins there — every other use of restPort in the function (URL parsing in the request handler, the self-warm fetches, the printed URL) already executes after listen() and picks the corrected value up via closure, so no other restructuring was needed.

Learned while delivering: Fix project switching: ensureAppDaemon in mcp/delegation/app-daemon.ts starts the target project daemon on DEFAULT_APP_PORT 3111, which the CURRENT daemon already occupies, so the child dies on EADDRINUSE and the switch times out after 15s. Fix: when starting a daemon because none is healthy, request an ephemeral port (--port 0), and make startDaemon in mcp/daemon.ts honor it honestly - after server.listen() succeeds, read the ACTUAL bound port from server.address() and use that real port everywhere the requested port is used: the status.json it writes (which ensureAppDaemon polls), the guard allowed origins (loopbackOrigins is currently computed from the requested port BEFORE listen - restructure so the guard uses the actual port), the self-warm fetches, and the printed URL. An explicitly requested nonzero busy port must keep failing loudly - never silently move a port the user asked for. Tests: mcp/app-daemon.test.ts has a spawnFn seam - assert spawn args request port 0 when starting fresh; unit-test the port resolution seam rather than booting a full daemon. Behavior must be unchanged when a healthy daemon already exists. Success = npm test fully green.
Verified by: npm test --prefix mcp, diff-size, citations
