# The orchestrator wake-loop stayed dead because goal attachment happened AFTER the run finished, not at creation

> Second live orchestration goal harden the delegation loop ... f43f, 2026 08 18 with implicit attachment and durable e…

Second live orchestration (goal harden-the-delegation-loop-...-f43f, 2026-08-18) with implicit attachment and durable events both merged, and still zero kernel wakes. Root cause is ordering, not the queue: in mcp/index.ts the kage_dispatch handler runs `const result = await dispatchRun(...)` — which executes the WHOLE run, agent work and verification included — and only afterwards resolves the goal (explicit goal_id, else the thread's active goal) and calls attachRunToGoal. So for the entire life of the run goalForRun(runId) returns null, notifyManagerOfRunEvent returns at its first guard, nothing is appended to the goal's pending-events log (the file never even gets created), and the manager is never woken; the attachment only materializes once the run is already dead. Evidence: run created 09:51:01Z, goal record still had zero run_ids minutes later while the run was executing, attachment appeared only after it failed, and .agent_memory/goals/<id>/events.jsonl was never written. The durable-events code itself is correct — it appends before the liveness check, exactly as designed — it simply never got called. Fix: attach inside dispatchRun immediately after createRun (goalId threaded through DispatchOptions), resolve the goal id BEFORE dispatch in the handler, and apply the same rule to POST /runs: attachment must always precede execution. General lesson, third variant of the same shape this session: it is not enough for a link to exist — it has to exist BEFORE anything depends on it. reapRun had no callers, looksLikeGitRepo had no callers, and here the caller existed but ran too late.
Evidence: Goal record showed run_ids empty while the run was mid-flight and populated only after it failed; no events.jsonl in the goal directory; room history contains zero manager-delivered [kage event] frames (the only match was my own message text quoting the token).
Verified by: Live orchestration on the merged Goals build (620/620 green); handler source inspected at mcp/index.ts around the dispatchRun call.
