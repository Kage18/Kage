# Positioning decision: Kage is an orchestrator that manages your work; memory comes with it

> Owner decision, 2026 08 19: Kage leads as an ORCHESTRATOR that manages your work the way AO and Conductor do. Memory …

Owner decision, 2026-08-19: Kage leads as an ORCHESTRATOR that manages your work the way AO and Conductor do. Memory is what comes bundled with it — the differentiator, not the headline.

This inverts the emphasis the product currently ships with. The CLI's own tagline reads "repo memory, and an orchestrator that uses it", and the status framing written the day before led with the memory half and treated orchestration as the layer on top. That ordering is now wrong. Lead with managing work; memory is why the management is better than the competition's.

What the decision changes in practice:
- The Room, Goals and Work surfaces are THE product, not a UI over a memory store. The bar is whether Kage can run a real workday of parallel agent work better than AO or Conductor, judged on the orchestration experience first.
- Memory's job is instrumental: better briefs, no re-learning, and an independent verdict on whether work is real. It earns its place by making orchestration better, not by being the thing a user is asked to care about up front.
- Feature priority follows the manager's ability to actually manage. Anything that leaves the manager unable to run a plan outranks memory-quality work.

The gap this immediately exposes, measured the same day: there are ZERO goal tools on the MCP surface (grep -c "kage_goal" mcp/index.ts returns 0) and none in MANAGER_ALLOWED_TOOLS (manager-client.ts lists only kage_room_state, kage_events_since, kage_compile_brief, kage_dispatch, kage_task, kage_tell, kage_stop, kage_merge_run, kage_reject_run, kage_report, kage_judgment). manager-prompt.ts nonetheless instructs the manager to decompose work into waves and act as the orchestrator. So the manager can dispatch single runs but cannot create a goal, read its status, or advance a wave — goals are creatable only from the app's orchestrate shortcut. Under the previous framing that was a secondary gap; under this one it is the central defect, because "manages your work" is precisely what it cannot do.

Supersedes the memory-first ordering in earlier positioning notes. Does not change the underlying architecture — the delegation loop, the verification kernel and merge-ratification all stand; what changes is which half leads and therefore what gets built next.
Evidence: Stated directly by the owner on 2026-08-19: "kage needs to be an orchestrator that manages your work like AO and conductor, memory comes with it."
