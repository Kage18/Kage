# A child process's own start/end timestamps around a runCommandCheck call span the lock-...

> A child process's own start/end timestamps around a runCommandCheck call span the lock wait time too, so comparing tw…

A child process's own start/end timestamps around a runCommandCheck call span the lock-wait time too, so comparing two children's wall-clock windows for 'overlap' doesn't prove serialization (both show near-identical start times regardless) — the evidence log's own wait note is the direct, unambiguous signal that serialization occurred.

Learned while delivering: Serialize kernel verifications per machine — three runs failed verification today on three different timing-sensitive tests (delegation-api room-queue, delegation-api room round-trip, resume-budgets dispatchDetached), every one passing solo on the same tree including inside the failing worktree; the common factor was another kernel verification or a worker's inner test suite running concurrently (see the repo gotcha 'Concurrent kernel verifications on one machine flake each other'). Fix in mcp/delegation/verify.ts (or a small module it uses): before running a run's check suite, acquire a per-machine verification lock (a lock directory or O_EXCL lockfile under the OS temp dir keyed to the machine, NOT the project — two projects' verifications interleave the same CPU), waiting with a visible note in the check evidence when queued (verification honesty: the receipt should say it waited, and for how long, so a slow verdict is explained); stale-lock recovery must be crash-safe (holder pid dead => steal, with the steal noted); a KAGE_NO_VERIFY_LOCK=1 escape hatch for CI machines that intentionally parallelize across isolated executors. Do NOT serialize the cheap inspected checks (diff-size, citations, reachability) — only the executed command checks (tests, typecheck, app-parse) need the lock. Add tests: two concurrent verifications on stub runs serialize (second waits), a dead-holder lock is stolen, and the wait is recorded in evidence. Keep the lock module small and dependency-free. Suite green; cite files individually.
Verified by: npm test --prefix mcp, diff-size, citations, npx tsc --noEmit -p mcp/tsconfig.json, reachability
