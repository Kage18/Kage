# The reported 6-minute-timeout-blank-turn bug is in mcp/delegation/api.ts's resolvePtyRe...

> The reported 6 minute timeout blank turn bug is in mcp/delegation/api.ts's resolvePtyReply the PTY leg, keyed on its …

The reported 6-minute-timeout-blank-turn bug is in mcp/delegation/api.ts's resolvePtyReply (the PTY leg, keyed on its own PTY_REPLY_TIMEOUT_MS constant, which just happens to numerically match room-supervisor.ts's ROOM_ASK_TIMEOUT_MS by design/comment), not in the headless leg (askRoomSupervisor/askManager) — the headless one-shot fallback (manager-client.ts's parseManagerStream) already guards against empty text via `guarded.text || "(the manager returned nothing)"`, so it was never the source of a blank persisted turn.

Learned while delivering: Room honesty bug, reproduced live today: when the room manager fails to answer within ROOM_ASK_TIMEOUT_MS (6 min, room-supervisor.ts), the pipeline records a NORMAL kage turn with empty text — the app shows a blank KAGE reply marked DONE (two real occurrences in .agent_memory/room/history.json at 2026-08-20T21:55:53 and 2026-08-21T07:26:01, both exactly 360s after the user message; the underlying pty claude session was a day old and wedged, while /room/pty/status still said alive:true because the process existed). Fix three things: (1) NEVER persist an empty timed-out reply as a normal turn — on ask timeout, record a visibly-failed kage turn whose text states plainly that the manager did not answer within the window and what recovery happened, and mark it so the renderer styles it as a failure, not prose (there is an existing test 'a manager failure becomes a visible kage turn instead of a silently dropped reply' — the timeout path must flow through that same mechanism; extend the test to cover the timeout-empty case so it can never regress); (2) on ask timeout, health-check the pty session honestly: alive must mean answering, not merely process-exists — after a timed-out ask, recycle the pty supervisor (kill and respawn fresh) so the NEXT message gets a live manager instead of another 6-minute void, and say so in the failure turn; (3) guard against wedged-forever sessions: if a pty supervisor is older than 12 hours at ask time OR its last completed ask timed out, recycle before asking. Keep the recycle logic in room-supervisor.ts/room.ts where liveness already lives; do not touch the delegation run supervisors. Suite green; cite files individually.
Verified by: npm test --prefix mcp, diff-size, citations, npx tsc --noEmit -p mcp/tsconfig.json, node --check <composed inline script>, reachability
