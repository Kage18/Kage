# Provenance must be one git pass: per-packet git log made the console 13x slower

> Showing who taught the repo each memory was spawning one git log per packet file. On this repo that is 299 process sp…

Showing who taught the repo each memory was spawning one git log per packet file. On this repo that is 299 process spawns and it cost 12.4 seconds, which made the whole console feel broken on open. The fix is mcp/delegation/provenance.ts: a single git log with the name-only flag scoped to the packets directory, walked newest first so the first appearance of a path is its last author, giving a packet id to author map in ONE spawn. It is cached per project with a fingerprint of newest packet mtime plus file count, so the cache refreshes exactly when a packet is written or ratified and never goes stale. Both the console notebook and the brief compiler use it. Two companion lessons: process spawn count, not algorithmic complexity, is the usual cause of slow CLI tooling on a large store, so measure spawns first; and the console now loads memory lazily on first visit to that screen rather than at startup, because opening a console must feel instant and the notebook is one keypress away. Remaining measured costs after the fix, all acceptable: recall 1.3s on the first call then about 230ms warm, code graph query 180ms then 83ms, CLI cold start about 0.5s of node plus kernel module load.
Verified by: measured on this repo (299 packets): memory load 12.4s to 0.93s cold and 25ms cached; console startup 12.9s to 0.34s; npm test 421 unit + 12 dogfood pass
