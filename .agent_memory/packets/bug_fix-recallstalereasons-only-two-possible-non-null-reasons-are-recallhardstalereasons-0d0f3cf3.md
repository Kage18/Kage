# recallStaleReason's only two possible non-null reasons are: recallHardStaleReason's res...

> recallStaleReason's only two possible non null reasons are: recallHardStaleReason's result 'packet status is X' / 'us…

recallStaleReason's only two possible non-null reasons are: recallHardStaleReason's result ('packet status is X' / 'user or agent reported this memory stale' / 'freshness ttl expired (...)' / 'all cited files deleted since capture: ...') or, if that's null, staleMemoryReasons' 'linked path changed since memory was verified: ...' -- it never surfaces staleMemoryReasons' 'some/all referenced paths are missing' reasons, those are packet-recall-only signals.

Learned while delivering: CRITICAL bug in the just-merged beliefs-first recall (mcp/kernel.ts's beliefStaleReason, called from recallBeliefs): it withholds a belief whenever ANY packet it cites has been superseded or deprecated -- recallStaleReason returns a reason mentioning packet status deprecated/superseded for those, and beliefStaleReason treats that identically to a broken/moved-code staleness reason, withholding the WHOLE belief. Measured impact (reproduced live via node -e against dist/kernel.js): 54 of 60 merged beliefs are invisible to recall right now; 46 of those purely because of a deprecated/superseded citation. This defeats the point of consolidation -- a belief is a synthesis that deliberately cites historical episodes including ones later superseded by newer learnings; citing superseded evidence is normal and correct, not a grounding failure. THE FIX: beliefStaleReason must only withhold a belief for citations that indicate the packet's claim itself may be wrong or its grounding broken -- a cited path that moved or was deleted under it, or the packet file being missing entirely. A cited packet whose status is deprecated or superseded or rejected_junk is normal lineage and must NOT withhold the belief. Read recallStaleReason to find the exact distinguishing signal between a terminal-status reason and a real grounding-failure reason, then change beliefStaleReason to skip the terminal-status case while still catching real grounding failures. Add a regression test: a belief citing only a deprecated-but-otherwise-grounded packet is served not withheld, and a belief citing a packet with genuinely moved or missing code is withheld. Verify the fix by running every belief in .agent_memory/beliefs/ against its own title as a query via recall() and reporting served vs withheld counts in your claim -- target near 60 served. Repo memory packet repo:https-github-com-kage-core-kage:bug_fix:beliefstalereason-conflated-packet-lineage-status-deprecated-superseded-with-gro has the full diagnosis if useful. Suite green; cite files individually.
