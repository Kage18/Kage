# reachability.ts's analyze() previously had no concept of module-level reachability at a...

> reachability.ts's analyze previously had no concept of module level reachability at all — only symbol level reachabil…

reachability.ts's analyze() previously had no concept of module-level reachability at all — only symbol-level reachability seeded from literal references inside the four root files. A bare top-level statement (not matching any DECL_PATTERNS) leaves currentScope null for its entire body, so every line inside it (including nested arrow/function expressions) gets lineOwner === null; this is exactly the shape of hook-registration patterns like contract.ts's onRunTransition(callback), and any future module-scope-executed pattern in this codebase will hit the same blind spot unless it goes through the new isModuleScopeStatement path.

Learned while delivering: The reachability check is blind to module-scope side effects, and one blind spot is cascading into a chain of false positives on every receipt.

MEASURED on the current tree. findOrphans reports these as unreachable; every one is genuinely used in production code:
- maybeAutoMerge — called at mcp/delegation/ratify.ts:240.
- syncGoalCompletion — called at mcp/delegation/goal.ts:290.
- autonomyGateForType — imported at mcp/delegation/ratify.ts:28 and used.
- AUTO_MERGE_MIN_VERIFIED_RATE — used at mcp/delegation/trackrecord.ts:128.

ROOT CAUSE, one bug not four. Both ratify.ts:240 and goal.ts:290 sit INSIDE a callback passed to onRunTransition(...) at MODULE SCOPE — the hook-registration pattern contract.ts's transitionRun invokes. A module's top-level statements execute when the module is imported, so a call registered there is genuinely reachable whenever the module itself is reachable from an entry point. The analyzer does not model this, so it marks maybeAutoMerge unreachable; then, because reachability is transitive, everything reachable ONLY through maybeAutoMerge is marked unreachable too — autonomyGateForType, and in turn AUTO_MERGE_MIN_VERIFIED_RATE. One missing rule produces a cascade.

WHY IT MATTERS: this check is advisory and prints on every claim receipt. Four wrong names on every receipt is how an advisory check gets ignored, and an ignored check is worse than none because it occupies a receipt line and implies coverage that is not there. We already paid once to raise this check's precision; this is the remaining systematic gap.

WHAT TO FIX in mcp/delegation/reachability.ts: treat top-level executable statements of a REACHABLE module as reachable roots. Concretely, if a module is reachable from an entry point (cli.ts, index.ts, daemon.ts, delegation/api.ts, bin entries), then identifiers referenced from its module-scope statements — including inside function expressions and arrow functions passed as arguments at module scope — are reachable. Do not special-case the name onRunTransition; the rule is about module-scope execution generally, and hard-coding one function name would leave the next registration pattern broken.

ACCEPTANCE BAR, state each result explicitly in your claim: after your change, findOrphans over mcp/delegation/ratify.ts, mcp/delegation/goal.ts and mcp/delegation/trackrecord.ts must NOT report maybeAutoMerge, syncGoalCompletion, autonomyGateForType, or AUTO_MERGE_MIN_VERIFIED_RATE. It must still report a genuine orphan — construct one in a fixture and prove the check still catches it, so this does not become a change that simply silences the rule.

TESTS — add to the existing mcp/reachability.test.ts (this file is already the home for this check's tests, so it is the right place; the new-file rule is about not appending to mcp/delegation.test.ts). Cover: a symbol called only from inside a module-scope callback is reachable; the transitive case (a helper used only by that symbol is also reachable); a genuinely unreferenced export is STILL reported; and the four real names above are not reported. Name in your claim which test fails if the change is reverted.

CONSTRAINTS: CommonJS — no import.meta (TS1470), no top-level await. Change mcp/delegation/reachability.ts and mcp/reachability.test.ts only. Do NOT touch mcp/cli.ts, mcp/kernel.ts, mcp/delegation/dispatch.ts or mcp/delegation/supervisor.ts — other runs are editing those.
VERIFY: npm run test --prefix mcp (692 green before your change) and npm run build --prefix mcp with no "error TS". Run them for real and fill in the claim fence.
