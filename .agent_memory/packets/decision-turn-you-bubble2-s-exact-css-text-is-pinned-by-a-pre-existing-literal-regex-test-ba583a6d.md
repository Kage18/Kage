# `.turn.you .bubble2`'s exact CSS text is pinned by a pre-existing literal-regex test in...

> .turn.you .bubble2 's exact CSS text is pinned by a pre existing literal regex test in audit driven parity pass.test.…

`.turn.you .bubble2`'s exact CSS text is pinned by a pre-existing literal-regex test in audit-driven-parity-pass.test.ts (mcp/audit-driven-parity-pass.test.ts:164) — any future visual change to that rule must add a SECOND rule block for the same selector rather than editing the first in place, unless that test is explicitly updated too.

Learned while delivering: Visual foundation pass on the app's Room chat, sidebar and board headers — presentation only, no behavior changes. The shipped app fails its own design source (docs/design/mockups/Main.dc.html and Board.dc.html — open them in a browser; their CSS is the spec) on structural typography and rhythm, and the owner has called the result out. Fix exactly these, by treatment: (1) THREAD COLUMN — the chat thread currently hugs the left edge with a huge right void; constrain the message thread to a max-width around 760px, centered within the chat pane with even gutters, composer aligned to the same column. (2) TYPE HIERARCHY — KAGE replies become real prose: 15px/1.7 body color var(--text), paragraphs spaced; YOU messages 14.5px in their green-left-bar block with background var(--surface) tint, radius 12, padding 12px 16px, the YOU/KAGE role labels 10px mono letterspaced var(--text3) sitting 6px above their block; stop rendering all content at one flat size. (3) TURN META — the floating right-aligned 'DONE · 5D' separators are noise: replace with a quiet inline meta line inside the thread column under each kage reply (10px mono var(--text3), e.g. 'done · 5d · 2 tools'), no full-width hairline floats. (4) TOOL LINES — consecutive 'ran X · Y' tool lines collapse into one toolgroup chip row per reply ('ran 3 tool calls' style, expandable if an expander already exists — if none exists, a static grouped chip row is enough, do NOT build new interaction). (5) BLOCK RHYTHM — vertical spacing between turns 26px, between label and block 6px, between reply and its meta 8px; kill the cramped 4px stacking. (6) SIDEBAR HIERARCHY — project rows get name 13px weight 600 var(--text) over path 10.5px mono var(--text3), 10px 14px padding, active project row filled var(--surface) with radius 10 and the green dot vertically centered; the Orchestrator/runs entries under the active project indent with a 12px left rule like the mockup; section labels use the existing seclabel treatment. (7) BOARD HEADERS — zone headers stop mushing ('IDLE / WORKING / REVIEWING' cramped): each zone header is a seclabel row with its count chip right-aligned, 14px padding below before the first card, per Board.dc.html. (8) COMPOSER HINTS — the hint line under the composer becomes one centered quiet line, 10px mono var(--text3), separators as middots, not a full-width sprawl. Do not change any behavior, handler, state, or API call; CSS and minimal DOM-structure changes in mcp/delegation/app-styles.ts and app-client.ts render functions only; keep every existing test green including composed-page parse and the CSS custom-property/class-usage tests (update those two tests' expectations only where a class was genuinely added/renamed); template-literal constraints as always (doubled escapes, no backticks or dollar-brace, h() only, never innerHTML). Both themes must stay legible — check the light token overrides for any new surface you tint. Cite files individually.
