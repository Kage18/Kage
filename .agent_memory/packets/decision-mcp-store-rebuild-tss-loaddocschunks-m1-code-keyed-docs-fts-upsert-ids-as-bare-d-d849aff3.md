> mcp/store/rebuild.ts's loadDocsChunks M1 code keyed docs FTS upsert ids as bare ${doc path} ${anchor} , which collide…

mcp/store/rebuild.ts's loadDocsChunks (M1 code) keyed docs-FTS upsert ids as bare `${doc_path}#${anchor}`, which collides whenever one long doc section splits into multiple DOCS_CHUNK_MAX_CHARS-sized chunks under the same heading (very common for prose docs, including this repo's own docs/design/MEMORY_STORE.md) -- upsert-by-id then silently keeps only the last chunk. Measured on this repo's real docs: 941 real chunks collapsed to 77 (one per doc) before the id got an index suffix (${doc_path}#${anchor}#${index}). Fixed in this run; any future code that builds a docs-FTS id from doc_path+anchor alone needs the same disambiguator.

Learned while delivering: M2 of the memory store: route the memory-side reads and writes through the StoreBackend seam that M1 just landed in mcp/store/ (merged to release-prep today - read mcp/store/types.ts for the interface contract and docs/design/MEMORY_STORE.md for the laws; both are on your branch).

WHAT TO BUILD:
1. kernel.ts's memory-side index layer goes through openStore(projectDir): the catalog, by-path/by-tag/by-type lookups, the BM25 docs index, and the vector store. Find every site that reads or writes .agent_memory/indexes/{catalog,by-path,by-tag,by-type,docs-index,vector-local}.json and route it through the seam. The JSON backend must keep TODAY'S files and semantics byte-for-byte compatible (an existing repo upgrades with zero migration; the json backend IS the current behaviour). The sqlite backend gets the same data in its tables, with FTS5 serving the BM25 role.
2. RECALL RESULTS MUST BE IDENTICAL ACROSS BACKENDS. The ranking math stays where it is today - the store serves rows, not rankings (M1's json.ts already states this contract). Golden test: build a small fixture repo with a handful of packets, run the same recall query against both backends, assert the same packet ids in the same order. This is the single most important test in the run.
3. `kage store status` and `kage store rebuild` CLI commands (mcp/cli.ts): status prints active backend, schema version, table/file counts, sizes; rebuild calls M1's rebuildStore and reports what it regenerated. Wire them into the help under a store section. These are the first user-visible surface of the store - keep the output in the CLI's existing voice.
4. Backend selection: openStore's manifest decides; default remains json until a user opts in OR node:sqlite is available AND the manifest records a completed migration - state in your claim exactly which policy you implemented (the design doc's lazy-migration language is the contract; if you deviate, say why in the claim and update the doc plus its guard test accordingly - you MAY edit docs/design/MEMORY_STORE.md and mcp/store-doc.test.ts for exactly that truth-sync purpose).
5. Perf smoke, honest numbers: time a rebuild and a recall on this repo's real .agent_memory with both backends and put the measured numbers in your claim - labelled measured, machine-local. No targets-as-claims.

TESTS - new file mcp/store-port.test.ts (repo rule: new behaviour gets its own file; mcp/delegation.test.ts is off-limits). Cover: the golden cross-backend recall equality; json backend byte-compatibility (writing through the seam produces files today's readers accept - round-trip through the OLD read path); sqlite backend round-trips the same fixture; `kage store status` names the active backend; rebuild is idempotent (second run changes nothing). Name in your claim which test fails if the change is reverted.

CONSTRAINTS: CommonJS - no import.meta, no top-level await. Zero new npm dependencies - package.json's diff must be empty. Your files: mcp/kernel.ts, mcp/cli.ts, mcp/store/** and your new test file (plus the doc+guard ONLY for the truth-sync in item 4). Do NOT touch anything under mcp/delegation/ (another run owns verify/ratify/contract/worktree-guard right now), mcp/index.ts, mcp/daemon.ts, mcp/api anything. Build and test ONLY inside your own worktree - never run npm, tsc or node against /Users/kushaljain/code/Kage.
