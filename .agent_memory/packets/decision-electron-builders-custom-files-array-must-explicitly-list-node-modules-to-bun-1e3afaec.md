# electron-builder's custom `files` array must explicitly list `node_modules/**/*` to bun...

> electron builder's custom files array must explicitly list node modules/ / to bundle a runtime dependency — the packa…

electron-builder's custom `files` array must explicitly list `node_modules/**/*` to bundle a runtime dependency — the packaged asar confirmed it correctly prunes devDependencies (electron, electron-builder) automatically even with a wholesale node_modules glob, so this is safe to do broadly.

Learned while delivering: Add auto-update to the Kage desktop shell (shell/) and finish the .dmg distribution pipeline. Requirements: (1) add electron-updater as a shell dependency and wire it in main.js behind a small separate module (shell/update.js) so the policy is readable: check on launch after the window shows and every 4 hours, download in background, and when an update is ready surface it non-modally (dock badge + a native notification or menu item 'Restart to update…' that calls quitAndInstall) — never interrupt a working session with a modal; (2) electron-builder config: add a zip target alongside dmg for mac (Squirrel.Mac updates from the zip; the dmg stays the human download), and a publish config for GitHub releases on this repo so electron-builder emits latest-mac.yml; (3) honesty about signing: auto-update on macOS only works for Developer-ID-signed builds — detect the ad-hoc case (reuse the existing developerId() detection at build time, and at runtime catch updater errors) and degrade to notify-only: tell the user a new version exists and open the releases page, never pretend an update installed; (4) the updater must be inert in dev (app not packaged) and respect an env kill-switch KAGE_NO_AUTO_UPDATE=1; (5) update shell/README or a comment block in update.js documenting the release flow: bump versions in lockstep (mcp + shell), build dmg+zip, publish the GitHub release with latest-mac.yml. Do not add any other dependencies. Keep main.js's zero-HTML rule — no renderer code in shell. The mcp test suite must stay green; add pure-logic tests only if a seam already exists for them, otherwise document why the updater is verified by packaging rather than unit tests.
Verified by: npm test --prefix mcp, diff-size, citations, npx tsc --noEmit -p mcp/tsconfig.json, reachability
