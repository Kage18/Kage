# The manager loop works headlessly; Ask pane and judgment recording proven live

> A headless manager session works end to end and is now reachable from the console. Proven live: claude runs non inter…

A headless manager session works end to end and is now reachable from the console. Proven live: claude runs non-interactively with the mcp-config flag plus allowedTools plus append-system-prompt, calls kage_room_state, kage_compile_brief and kage_dispatch in the order the constitution specifies, and each run records its judgment. Measured cost was 13 to 25 seconds and 0.15 to 0.22 dollars per manager turn on a tiny repo, with stub workers so only manager tokens were spent. Two integration facts that are easy to get wrong: the client may hide MCP tools behind ToolSearch so ToolSearch must be in allowedTools or the manager can see the tools but never load them; and the one-shot nature of the print flag means continuity has to come from replaying recent turns in the prompt, which is a transcript rather than a resumed session. The console gained an Ask screen backed by the same client, running out of band so the board stays live while the manager thinks. Two UX laws confirmed while building it: every text-entry mode must swallow printable keys before global shortcuts, and a modifier key must mean ONE thing everywhere — tab previously cycled the run type on the dispatch screen and switched screens elsewhere, which trapped the user on that screen, so type cycling moved to the arrow keys. Honest gap observed: the manager restated card numbers in prose despite the constitution forbidding it.
Verified by: live 3-turn manager session on a seeded repo: room_state then compile_brief then dispatch, judgment recorded per run, 13-25s and 0.15-0.22 USD per turn; npm test 431 unit + 12 dogfood pass
