# Goal attachment must not depend on the manager remembering goal_id — the orchestrator loop needs implicit goal context

> First live orchestration goal harden the verification loop ... d82d, 2026 08 18 worked at the planning layer and fail…

First live orchestration (goal harden-the-verification-loop-...-d82d, 2026-08-18) worked at the planning layer and failed at the wiring layer. The manager did everything the constitution asks: compiled a brief per intent BEFORE proposing, spotted that both predicted touch sets included the shared mcp/delegation.test.ts and warned about a second-merge conflict, attached track-record confidence per run type, cited the relevant memory for each, stated it would pass goal_id, and stopped for approval instead of dispatching unilaterally. But the dispatched run carried NO goal_id, so attachRunToGoal never ran, the goal record kept zero waves, goalForRun returned null, and the event bridge in room-supervisor.ts — which only wakes the manager for goal-owned runs — could never fire. Verified it was not a stale-process problem: mcp/dist/index.js contained goal_id and was built at 12:32:30, while the room supervisor and its MCP server started at 12:34:29. So the capability and the instruction were both present and the parameter was still dropped. The structural lesson (same shape as reapRun-with-zero-callers and spec-without-test): a loop whose closure depends on an agent REMEMBERING to pass a parameter is a loop that will open. Fix direction: make goal context implicit — the room session that owns a goal stores active_goal_id, and the kage_dispatch handler (running with KAGE_ROOM=1 in that session's MCP server) attaches to it automatically unless an explicit goal_id overrides; the manager should not be able to forget. Keep the explicit parameter for non-room callers.
Evidence: Goal record showed plan.waves = 0 after dispatch; the dispatched run in-mcp-delegation-supervisor-ts-run-chea-260818-d778 had no goal_id and goalForRun returned null; build/process timestamps ruled out a stale MCP schema.
Verified by: Live orchestration attempt on 2026-08-18 with the merged Goals O1/O2 build (603/603 tests green).
