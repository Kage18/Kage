# The Room never dispatched until now: headless managers need --allowedTools; reapRun had zero callers

> Two release critical bugs found from one user screenshot "it's still stuck" . 1. The held room manager was permission…

Two release-critical bugs found from one user screenshot ("it's still stuck").

1. The held room manager was permission-denied on EVERY kage MCP tool since the live session shipped. room-supervisor.ts spawned `claude -p` with `--permission-mode acceptEdits` but no `--allowedTools` — acceptEdits covers file edits only, and -p is headless so no permission dialog exists anywhere. The manager looped asking the user to "approve in the permission prompt"; typing "grant" in chat did nothing because there was nothing to grant into. Consequence: the Room's core promise ("dispatch, merges and answers all happen by talking") had NEVER executed — every earlier "manager tax" measurement was actually the manager asking for permissions. The one-shot fallback in manager-client.ts always passed `--allowedTools [...MANAGER_ALLOWED_TOOLS, "ToolSearch"]` — fourth drift of the identical shape (claim writers, stream readers, spend recorders, spawn args): the fallback/tested path configured correctly, the live path not. Fix: shared allow-list in both spawn sites + a source gate requiring `--allowedTools` and `MANAGER_ALLOWED_TOOLS` in both files. Verified live: after retiring the tool-less manager (retireStructuredRoom) and letting a fresh one spawn with --resume (context survives), the manager called kage_compile_brief → kage_dispatch and the run reached ready.

2. reapRun ("persist death") existed with ZERO callers — the law was written, tested conceptually, and never executed. Dead runs stayed derived-"dropped" forever, holding concurrency slots. Separately, liveState did not count "verifying" as in-flight (only running/dispatched), so pid-dead verifying runs derived nothing and sat at "verifying · no activity yet" for 16 hours. Fixes: verifying joins the in-flight set; sweepDeadRuns(projectDir, graceMs=5min) persists death for every derived-dropped run past grace; the daemon sweeps at startup and every 60s (unref'd timer, failures swallowed). Verified: first startup sweep persisted both 16-hour rows to failed.

Durable rules: (a) any headless `claude -p` spawn that expects MCP tools MUST pass --allowedTools — there is no dialog to save you; (b) grep for callers of every "law" function — a written invariant with zero call sites is a lie in waiting; (c) when a fallback and a live path exist, the live path is the untested one.
Evidence: User screenshot showed the manager asking to approve mcp__kage__kage_room_state in a dialog that cannot exist in -p mode. grep confirmed --allowedTools present in manager-client.ts and absent in room-supervisor.ts; reapRun had no call sites outside its export. After fixes: room turn used tools ['kage_compile_brief','kage_dispatch'] and the mod7 run reached ready; startup sweep left zero runs in verifying (both 16-hour rows persisted to failed).
Verified by: npm test — 562 pass 0 fail exit 0, including the spawn-site gate and the sweepDeadRuns grace/idempotence test; live Room dispatch on the bigrepo daemon; commit 8853f45
