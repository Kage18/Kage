# Three gates now cover silent renderer failures — comparisons, custom properties, and orphan classes

> The renderer mcp/delegation/app html.ts is one TypeScript template literal holding hand written client JS and CSS, so…

The renderer (mcp/delegation/app-html.ts) is one TypeScript template literal holding hand-written client JS and CSS, so TypeScript checks none of it. Three distinct failure shapes there produce NO error and only a quietly wrong UI. All three shipped in real sessions, and all three were found by looking at a screenshot while the whole suite was green. Each now has a textual gate in mcp/delegation-api.test.ts, and each gate was mutation-tested by reintroducing the bug into dist and confirming the right failure message.

1. A string comparison against vocabulary the kernel never emits. `r.ownership === "human"` where Ownership is working|needs_you|done — the branch never fires, so the "needs you" badge could never appear. The gate scans for ownership/display_state comparisons and checks each value against the real union, importing RUN_STATES from contract.ts rather than restating it (a hand-copied list in the test has the same defect it guards against — it did, flagging "draft" on its first run).

2. An undefined CSS custom property. `var(--warn)`, `var(--bad)`, `var(--shadow)` — the declaration is silently dropped, so a badge renders as plain text with no pill. The gate asserts every var(--x) used in the stylesheet is defined in it.

3. A styled class no element carries. `.mem-health` was styled as a six-column grid while the markup only had id="mem-health", so six stat tiles stacked full width. The gate collects class selectors from the CSS and requires each to appear in the markup or in an h(tag, "class") call, with explicit exemptions for classes built by concatenation ("chip state-" + state) and for the vendored xterm stylesheet.

Each gate also asserts it FOUND a minimum number of things to check. That is not ceremony: the CSS-variable gate's own slice was briefly broken and found nothing, and without that assertion it would have passed vacuously forever.
Evidence: Mutation-tested: reintroducing `ownership === "human"` fails with 'the renderer compares ownership against "human", which the kernel never emits'; `var(--amber)` → `var(--warn)` fails with 'these custom properties are used but never defined: --warn'. The orphan-class gate flagged .mem-health and the dead .sealc rule on its first run.
