# When verifying this repo's own verify-lock fix, the operator must run its own outer `np...

> When verifying this repo's own verify lock fix, the operator must run its own outer npm test with KAGE NO VERIFY LOCK…

When verifying this repo's own verify-lock fix, the operator must run its own outer `npm test` with KAGE_NO_VERIFY_LOCK=1 as a bootstrap escape hatch (since the pre-fix kernel would otherwise deadlock on itself) — any future test added to serialize-kernel-verifications-per.test.ts or verify-lock-reentrancy.test.ts must be written assuming that variable, plus KAGE_VERIFY_LOCK_HELD and KAGE_VERIFY_LOCK_PATH, may already be set in the ambient environment it runs under, not just in a clean CI shell.

Learned while delivering: Critical reentrancy bug in the just-merged verification lock (mcp/delegation/verify-lock.ts + verify.ts): spawnWithTreeKill acquires the per-machine lock for EVERY executed command, so the kernel's outer verification holds the default lock for the entire npm-test run — and any test inside that suite whose code path reaches spawnWithTreeKill without overriding KAGE_VERIFY_LOCK_PATH blocks forever on its own ancestor's lock (holder pid is alive, so the steal path never fires) until the 1200s tree-kill. This is what failed run visual-foundation-pass-on-the-app-s-room-260821-be77: tests.log exit 124 after 1200s while the agent's own inner suite (no outer lock held) ran green. Fix by environment-token reentrancy: when acquireVerifyLock actually acquires (not skipped, not stolen), export a held marker into child processes — spawnWithTreeKill already builds the child env, add KAGE_VERIFY_LOCK_HELD=1 there — and acquireVerifyLock returns immediately as 'inherited' when that marker is present, because a nested execution is part of the same serialized unit; record 'lock inherited from parent verification' in the evidence note instead of a wait. The existing lock tests must keep testing REAL acquisition: their spawned child scripts already set KAGE_VERIFY_LOCK_PATH — have them also delete KAGE_VERIFY_LOCK_HELD in the child env so the nested-marker never leaks into them from the test runner itself. Add one regression test: a stub verification executed INSIDE an environment where KAGE_VERIFY_LOCK_HELD=1 completes immediately without waiting on a held default lock. Keep the module dependency-free; suite green; cite files individually.
