# Prompt-only rules leak: enforce the no-restated-numbers law in the kernel

> The manager constitution forbids restating any number from a kernel card, and the manager broke that rule in its firs…

The manager constitution forbids restating any number from a kernel card, and the manager broke that rule in its first live session and again after the first guard shipped. This is the general failure of prompt-only rules: a model that paraphrases a verdict can paraphrase it wrong, and a wrong verdict in friendly prose is exactly what this product exists to prevent. The fix is guardManagerProse in mcp/delegation/manager-client.ts, applied on the way out of parseManagerStream so every consumer gets guarded text: verdict words, N-slash-M counts, the phrase all N checks, N-line diff sizes, N files changed, and dollar costs are replaced with a pointer to the card, and the replaced strings are returned as redactions so the console can say the kernel edited the reply rather than editing it silently. Two calibration lessons. First, the guard must be surgical: a number that belongs to a memory rather than a card, such as a backoff cap of 3 attempts, must survive, and so must pointers like retry.ts line 42, or the guard destroys the judgment that makes the manager worth having. Second, catching this needed a second pass because the count leaked in words rather than as a fraction, so patterns should be grown from observed leaks rather than imagined ones. Honest limitation: in kage room the manager owns the terminal directly, so Kage cannot intercept its prose there; the guard only applies where Kage relays the text, such as the console Ask pane and scripts.
