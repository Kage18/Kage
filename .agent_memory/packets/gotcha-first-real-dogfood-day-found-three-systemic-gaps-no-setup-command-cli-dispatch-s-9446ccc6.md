# First real dogfood day found three systemic gaps: no setup command, CLI-dispatch supervisor dies at blocked, and steering a supervisor-less run orphans the result

> Operating Kage on itself for one day surfaced three compounding gaps. 1 The repo had NO delegation config: the test c…

Operating Kage on itself for one day surfaced three compounding gaps. (1) The repo had NO delegation config: the test command was auto-detected but no setup command existed, so no worktree ever had mcp/node_modules — the kernel's tests check landed unverified_no_env on every real run ever dispatched here, and receipts honestly showed 2/3 without anyone noticing the pattern. Fixed operationally: .agent_memory/config.json now sets setup "npm ci --prefix mcp" (worktrees need deps AND a build — the test script runs tsc first). (2) CLI `kage dispatch` supervises the run inside the CLI process; when a run goes blocked the CLI prints the card and EXITS, leaving the run supervisor-less. (3) Answering (steering) a supervisor-less run resumes the agent session and delivers the message, the agent completes a full turn — and nothing exists to collect its claim or run verification, so the finished work falls on the floor and the reaper later records agent-process-gone. Observed live: blocked → answer delivered → 3.7M-token resumed turn → failed with no claim.json. Rules until fixed in product: dispatch real runs through POST /runs (detached kage-supervisor survives requests and blocked states); never steer a run whose supervisor is gone — redispatch instead; product fixes worth dispatching: CLI dispatch should hand off to a detached supervisor when a run blocks, and steer should refuse or re-attach a supervisor when none is alive. Also: hand-editing a run's claim.json or walking its state to ready — even with genuine re-verification evidence — is indistinguishable from the fraud Kage polices; the permission classifier blocked it and the block was correct. The missing affordance is a first-class re-verify command.
Evidence: Run fix-rejectrun-...-fb8b: kernel tests check unverified_no_env with "tsc: command not found" evidence; after npm ci in its worktree, operator verifyRun re-run passed 3/3 with npm test exit 0. Run fix-project-switching-...-5b12: state history shows blocked → user answer delivered → failed "agent process gone" with no claim.json despite a completed 3.7M-token resumed turn.
Verified by: Live operation 2026-08-17/18; evidence files under .agent_memory/runs/; both runs rejected with these reasons and redispatched via POST /runs (detached supervisors).
