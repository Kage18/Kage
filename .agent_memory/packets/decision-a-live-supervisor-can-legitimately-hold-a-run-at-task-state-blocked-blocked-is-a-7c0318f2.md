> A live supervisor can legitimately hold a run at task.state === 'blocked' blocked is a WAITING state, the control soc…

A live supervisor can legitimately hold a run at task.state === 'blocked' (blocked is a WAITING state, the control socket stays open) — so confirming a supervisor has stopped must poll isRunLive() itself, not task.state leaving 'running', or the wait never fires for a blocked-but-live run.

Learned while delivering: PER-RUN TERMINAL TAKE-OVER backend (run 2 of 3, backend only — a parallel run owns steer/plan/interrupt plumbing and a later run owns all UI and API wiring; to avoid merge conflicts DO NOT touch api.ts, app-client.ts, app-html.ts, app-styles.ts, steer.ts, contract.ts, supervisor.ts — coordinate only through their existing exported functions). Build the AO-parity raw-access model for RUNS as a new module mcp/delegation/run-pty.ts, closely modeled on mcp/delegation/room-pty.ts (read it first — it solved the pty lifecycle, snapshot-on-attach, resize, and blank-pane repaint problems; reuse its patterns and its node-pty usage). Full loop, no compromises: (1) takeOverRun(projectDir, runId): validate the run has an agent_session_id and is in a state a human may seize (running, blocked, stopped, failed — never merged/rejected); if a live supervisor holds the run (isRunLive from control.ts), stop it cleanly first via the existing stop control so the held child exits and the run lands stopped — the take-over must never fight a supervisor for one session; then spawn an INTERACTIVE claude resuming that session (claude --resume <sessionId>, NO -p, real pty) with cwd = the run worktree (worktreePath from worktree.ts; refuse honestly if the worktree is gone), transition the run to running with by user and a note taken over in a terminal, and record the pty pid via patchRun agent_pid so liveState stays truthful. Expose the same surface room-pty offers its callers: write(data), resize(cols, rows), snapshot() returning scrollback, onData/onExit hooks, detach(). (2) handBack(projectDir, runId): kill the pty child cleanly, transition the run to stopped with note handed back from take-over, and spawn a detached reattach supervisor for the run exactly the way steer.ts part-2 does (same kage supervise spawn shape, detached, unref) so the run is supervised again and a subsequent tell or its own next fence completes normally — the full circle, take over then hand back then supervised. Also export takeOverState(projectDir, runId) reporting {active, pid} honestly. Keep everything seam-testable: accept an optional spawn/pty factory parameter like room-pty and app-daemon do, so tests never launch a real claude. Tests in a new mcp/run-pty.test.ts mirroring mcp/room-pty.test.ts patterns: take-over refuses terminal states and missing worktrees with plain reasons; take-over on a supervised run stops the supervisor first (assert via seams); state transitions and agent_pid land as specified; handBack transitions and spawns the reattach supervisor (spawn seam records args); snapshot/write/resize delegate to the pty seam. Success = npm test fully green.
