# kernel.ts stays one file — splitting was measured and is the wrong fix

> kernel.ts is ~21,000 lines, which reads as an obvious defect, so it was measured before acting. Three measurements sa…

kernel.ts is ~21,000 lines, which reads as an obvious defect, so it was measured before acting. Three measurements say the same thing:

1. 174 functions call nothing else in the file, but they total 1,679 lines — 8%. Extracting every leaf still leaves a 19,400-line file.
2. The generic helpers everyone assumes are the shared base (ensureDir, nowIso, readJson, writeJson, unique, repoKey) are 3-9 lines each. Pulling them into a base module moves about 50 lines.
3. Lifting out the best-candidate cohesive region — agent setup, 708 lines, one clear topic — required making SEVEN private internals public (AGENTS_POLICY_MARKER, ensureDir, nowIso, readJson, repoKey, unique, summarize) to satisfy its imports, and created an import cycle back to kernel.ts. Every region extraction has this shape because the region calls the memory core (indexProject, capture, learn, recall, observe).

So the file's size is a symptom of SEMANTIC coupling inside one domain, not of poor file organization. Moving code between files cannot fix that: it trades one large file for many files plus a wider public API plus import cycles, which is worse on every axis. A genuine decomposition means redesigning the memory core's internal boundaries — a design program with real regression risk against 551 tests and no user-visible benefit.

What WAS broken is navigation: 21,000 lines with 8 section banners and no header at all. Fixed instead — a header recording the measurements above, an index of eleven sections, and `§ MARKER` anchors through the body (searching "§ RECALL" jumps to recall). A test in release.test.ts asserts the index lists exactly the markers present, in the order they appear, so the map cannot drift from the territory.

Recommendation for the next person who opens this file and reaches for a refactor: don't, until a change actually requires different boundaries. Use the index.
Evidence: Leaf analysis: 174 functions with zero intra-file dependencies, 1,679 lines total against 21,103. Utility bodies read directly (ensureDir 3 lines, nowIso 3, unique 3, repoKey 9). The agent-setup extraction was actually performed as an experiment and typechecked: tsc reported seven TS2459 "declares X locally, but it is not exported" errors plus a missing import, confirming the API-widening effect; the experiment file was then deleted.
Verified by: npm test — 551 pass, 0 fail, real exit code 0, including the new index-vs-markers gate
