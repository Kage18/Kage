# Worktree isolation is enforced by worktree-guard, and a dying supervisor now leaves a log

> A hired agent's build could escape its worktree into the main checkout's gitignored mcp/dist — what the daemon and ev…

A hired agent's build could escape its worktree into the main checkout's gitignored mcp/dist — what the daemon and every newly spawned supervisor load — so the running system briefly executed unreviewed code from an in-flight run. Source never leaked; only build output did. Two properties of that incident still matter and are worth keeping in mind. First, rebuilding mcp/dist fixes the FILES but not already-running processes: a supervisor spawned during a contamination window keeps the leaked code in memory for its whole life, and one went on to write a stop note advertising a command that did not exist in the shipped build. Second, the leak is cwd-dependent — building with the worktree as cwd does not leak, which is how the mechanism was pinned. What has since changed: mcp/delegation/worktree-guard.ts now exists to enforce the boundary rather than leaving it a convention, and dispatchDetached no longer spawns with stdio: "ignore" — it passes a real log file descriptor (dispatch.ts, stdio: ["ignore", logFd, logFd]), so a supervisor that dies leaves a reason behind. The earlier packet's claim that there is "no log anywhere" is therefore obsolete. Unchanged and still true: command checks receive the worktree explicitly via runCommandCheck(projectDir, runId, worktreeDir, check), so verification itself always tested the right tree. When briefing an agent to act on records under the main repo's .agent_memory, still say explicitly that reading there is fine and building or writing there is not.
Evidence: Verified in the shipped build after merging run resume-run-cannot-resume-a-run-stopped-o-260819-2c7c: `grep -n stdio mcp/delegation/dispatch.ts` shows line 403 `stdio: ["ignore", logFd, logFd]` and line 390 a comment naming the old `stdio: "ignore"` as the defect. mcp/delegation/worktree-guard.ts and mcp/worktree-guard.test.ts exist on release-prep. Full suite green at 857 unit + 12 dogfood, 0 failures.
Verified by: grep of dispatch.ts in the merged build, presence of worktree-guard.ts, and npm run test --prefix mcp (857 + 12, exit 0)
