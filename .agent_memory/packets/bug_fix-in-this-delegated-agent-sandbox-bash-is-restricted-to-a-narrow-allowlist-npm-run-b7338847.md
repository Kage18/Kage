> In this delegated agent sandbox, Bash is restricted to a narrow allowlist: npm run build succeeds, but npm test , nod…

In this delegated-agent sandbox, Bash is restricted to a narrow allowlist: `npm run build` succeeds, but `npm test`, `node --test ...`, and even plain `node dist/x.js` are denied outright ('This command requires approval') with no interactive prompt reaching the agent — so dispatched agents fixing packaging/test-guard bugs in mcp/ should verify via `npm run build` plus static/manual reasoning and explicitly flag in their claim that Kage's own re-run is the actual test verification, rather than retrying test invocations.

Learned while delivering: Three release-blocking packaging defects. All three are verified facts, not guesses.

DEFECT 1 — the desktop app ships with the wrong version number.
mcp/package.json is 3.1.0 (the product version, what npm publishes). shell/package.json is still 0.1.0, and electron-builder derives the artifact name from it, so the built file on disk right now is literally 'shell/dist/Kage-0.1.0-arm64.dmg' for a 3.1.0 product. That version is what a user sees in the .dmg filename and the macOS About box.
FIX: set shell/package.json version to match mcp/package.json (3.1.0).

DEFECT 2 — the version-lockstep guard does not cover the package that drifted.
mcp/release.test.ts has a test 'distribution manifests stay in version lockstep with the npm package' whose comment says manifests drifted three minor versions behind npm before the guard existed. It checks ../server.json, ../plugin/.claude-plugin/plugin.json and ../plugin/.codex-plugin/plugin.json — but NOT ../shell/package.json, which is exactly the one that drifted. A guard that misses the newest package is how defect 1 happened.
FIX: add ../shell/package.json to that test's manifest list so this can never drift again. Note the test reads 'package.json' relative to cwd and the suite runs from mcp/, so keep the ../ convention the existing entries use. Confirm the test FAILS before your fix and PASSES after — state both in your claim.

DEFECT 3 — a native module can abort the entire npm install.
node-pty 1.1.0 is in mcp/package.json 'dependencies'. Its install script is 'node scripts/prebuild.js || node-gyp rebuild', so when the prebuilt binary cannot be fetched (offline, a proxy, an unsupported platform/arch) npm falls back to compiling, which needs Python and a C++ toolchain. If that fails, 'npm i -g' fails outright and the user gets NOTHING — even though the only features needing a pty are the optional terminal views. The code is already written correctly for absence: both mcp/delegation/run-pty.ts:40 and mcp/delegation/room-pty.ts:135 import it lazily with 'await import("node-pty")' precisely so every other command keeps working.
FIX: move node-pty from 'dependencies' to 'optionalDependencies' in mcp/package.json — npm treats a failed optional dependency as non-fatal and continues the install. Then make both lazy import sites degrade with a HUMAN message instead of a raw MODULE_NOT_FOUND: catch the import failure and surface something like 'The terminal view needs node-pty, which is not installed on this machine (it is an optional native module). Everything else in Kage works without it.' Do not swallow the error silently and do not change any other dependency.

CONSTRAINTS:
- Do NOT touch mcp/delegation.test.ts, mcp/delegation/app-client.ts, mcp/delegation/app-styles.ts, mcp/delegation/contract.ts or mcp/delegation-api.test.ts. Two other runs are editing those right now and any edit will cause a merge conflict. Your tests belong in mcp/release.test.ts.
- This project compiles to CommonJS. No 'import.meta' (TS1470), no top-level await.
- Do not run kage_refresh, kage_learn or kage_pr_check — those are the operator's job, not yours.

HOW YOU'LL KNOW IT WORKED:
- mcp/release.test.ts gains shell/package.json to the lockstep list and passes.
- Add a test asserting node-pty is in optionalDependencies and NOT in dependencies.
- Add a test that both pty modules reference node-pty only through a lazy import (no top-level static import of it), so a future refactor cannot quietly make it mandatory again.
- Run `npm test --prefix mcp`; the whole suite must stay green (627 tests before your change) and `npm run build --prefix mcp` must emit no 'error TS'.
