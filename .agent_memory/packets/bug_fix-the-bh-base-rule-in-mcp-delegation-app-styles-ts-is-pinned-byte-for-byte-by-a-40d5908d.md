# The .bh { ... } base rule in mcp/delegation/app-styles.ts is pinned byte-for-byte by a ...

> The .bh { ... } base rule in mcp/delegation/app styles.ts is pinned byte for byte by a literal regex in mcp/visual fo…

The .bh { ... } base rule in mcp/delegation/app-styles.ts is pinned byte-for-byte by a literal regex in mcp/visual-foundation-pass-on.test.ts:77 ('board zone header words are sentence case...'); like the .turn.you .bubble2 precedent already in repo memory, any visual fix touching that selector must add sibling/child rules (.bh-label, .bh i, .bh .sep, .bh .n) rather than editing .bh's own declaration block, unless that test is updated too.

Learned while delivering: Board zone headers regressed visually after the visual-foundation merge — owner screenshot shows, at a wide viewport: the compound zone header 'Idle / Working / Reviewing' wraps word-by-word with its counts fragmenting into a VERTICAL '0 / 0 / 0' stack on the right; 'Needs you / Changes requested' wraps mid-phrase across lines with its '0 / 0' breaking onto two rows; stray thin bar glyphs render before each zone word (check whether a dot/border element or a literal pipe character is being emitted per word); and on the run card the token count '6.4M tok' wraps 'tok' to its own line. Fix in mcp/delegation/app-styles.ts (+app-client.ts only if the DOM structure forces it): (1) each zone header is ONE flex row — status dot(s) + label text with white-space:nowrap, then a single right-aligned count atom; compound zones render their counts as one joined atom ('0 / 0 / 0') that never wraps and never stacks; if horizontal space is short the LABEL truncates with ellipsis, the count never wraps; (2) remove or fix the stray bar glyphs so each zone shows exactly one colored dot per zone name as in docs/design/mockups/Board.dc.html (its zone-header CSS is the spec — seclabel treatment, counts right-aligned); (3) chips and stat atoms on cards ('6.4M tok', '$… · …m', 'VERIFIED 5/5') get white-space:nowrap so they never split internally; (4) sanity-check both List and Board layouts and the narrow layout at ~390px — headers must degrade by truncating labels, never by stacking counts. Presentation only; parse test and suite green; the CSS custom-property and class-usage tests updated only for genuinely added/renamed classes; template-literal constraints as always; cite files individually.
Verified by: npm test --prefix mcp, diff-size, citations, npx tsc --noEmit -p mcp/tsconfig.json, node --check <composed inline script>, reachability
