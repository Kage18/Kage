# One derived state for every surface; sequence the ledger; never claim undelivered steers

> Three defects, all of them a surface telling a story the kernel already knew was false. First, derived state was comp…

Three defects, all of them a surface telling a story the kernel already knew was false. First, derived state was computed in two of four surfaces, so the TUI called a dead run dropped while the managers room state and the while-you-were-away digest still called it running. The fix is displayState and ownership in mcp/delegation/contract.ts, attached by readRun and listRuns as a RunView, so rendering the raw state is an opt-out rather than the default; a test now asserts that no surface anywhere prints running for a run whose process is gone. Second, steering a live agent returned a delivery of queued and said the message would join the brief at the next boundary, but the steer log is only consumed on retry, so nothing reached the running agent. The delivery vocabulary is now resumed, stored or refused, and the stored message says plainly that it was not delivered and names kage stop as the way to actually redirect. Third, the event cursor lost events: the page limit was applied after filtering so an answer could be silently truncated, and the cursor compared ISO timestamps as strings, so two events written in the same millisecond lost the second one permanently, which the manager hit at every turn boundary. Events now carry a monotonic sequence, the cursor is sequence based, and a truncated page reports how many it dropped. GOTCHA that only real data revealed: a ledger written before sequencing has no seq field at all, so the cursor never advanced and every poll re-read the whole history; readers now treat a legacy lines position as its sequence and the writer starts above the line count so new events cannot collide with that implicit numbering.
Verified by: npm test --prefix mcp: 445 unit + 12 dogfood pass; verified on the real repo where a run stuck 2547 minutes now reads dropped on the board, in room state and in the digest, and the ledger cursor advances from 0 to 22
