# The citation extractor is so eager it fails the run that describes it — and briefs must state this project is CommonJS

> Two brief level gaps proven by one orchestrated wave 2026 08 18 . 1 CITATION SELF TRAP: the run whose whole job was t…

Two brief-level gaps proven by one orchestrated wave (2026-08-18). (1) CITATION SELF-TRAP: the run whose whole job was tightening citedPaths in mcp/delegation/verify.ts failed its own citation check on the token state.room/state.pty — the very example its brief used to describe the bug. The extractor treats any slash-joined prose token as a cited file path, so a claim cannot even DESCRIBE the defect without tripping it. Three separate runs have now died this way (state.room/state.pty twice, a .agent_memory runtime path once), always with code and tests green. (2) COMMONJS: both agents in the wave independently failed verification with TS1470, import.meta is not allowed in files which build into CommonJS output, while appending tests to mcp/delegation.test.ts. Two agents making the identical mistake within minutes is a brief gap, not agent error — renderBrief in mcp/delegation/brief.ts must state the project compiles to CommonJS (no import.meta, no top-level await; use __dirname/__filename or require.resolve), alongside the line telling hired agents they never run harness tools (kage_refresh/kage_learn/kage_pr_check are the operator's job). General rule this session keeps re-teaching: when two independent agents fail the same way, fix the BRIEF, not the agents.
Evidence: Run mcp-delegation-verify-ts-citedpaths-trea-260818-2d31: citations.log shows ok verify.ts, ok delegation.test.ts, MISSING state.room/state.pty; tests.log shows delegation.test.ts(2037,32) TS1470. Sibling run mcp-delegation-brief-ts-renderbrief-must-260818-6762 failed with the same TS1470 at line 2044.
Verified by: Kernel evidence files from both runs of the second orchestrated wave.
