# The actual root cause of the crushed board-card title was NOT font-size or line-clamp (...

> The actual root cause of the crushed board card title was NOT font size or line clamp a webkit line clamp:2 rule alre…

The actual root cause of the crushed board-card title was NOT font-size or line-clamp (a -webkit-line-clamp:2 rule already existed on .acard .at) — it was that .acard was `display:grid; grid-template-columns:26px 1fr`, a leftover from a since-removed avatar element. fillBoardCard only ever appended ONE child div (wrapping both the title and the meta row) to that grid, so it auto-placed into the first (26px) column instead of the 1fr one, crushing everything inside it — the meta row's un-line-clamped branch slug then overflowed that same 26px box across the card's visible width, which is exactly the 'title crushed / slug dominates' symptom described.

Learned while delivering: Board cards crush the run's name into confetti - fix the card layout. Owner screenshot from the live app just now: in Board view every card renders its display_name in a column roughly five characters wide, so titles shatter into 'Writ / th...', 'Kill / th...', 'M4 / of...', 'Ever / d...' - while the raw run-id slug underneath ('write-if-changed-finish-the-render-calm-260820-3502') wraps across the card's FULL width and visually dominates. The sparse-card trim put the right content on the card but the title shares a flex row with the meta cluster (state dot, token count, verdict chip), which squeezes it to nothing at board-column widths; List view survives only because its rows are wider.

THE FIX, in mcp/delegation/app-client.ts and app-styles.ts:
1. Card layout becomes three stacked rows, each full card width: ROW 1 - display_name, up to two lines, overflow ellipsis on the second line (-webkit-line-clamp 2 with the existing fallback pattern if one exists in the stylesheet; otherwise single-line ellipsis is acceptable - state which you shipped). ROW 2 - the branch/slug chip, single line, TRUNCATED IN THE MIDDLE so both the leading words and the trailing -260820-xxxx serial stay readable (CSS direction tricks are fragile here - do it in JS when building the label: keep first ~18 and last ~12 chars with a single ellipsis between; state your exact split). ROW 3 - the meta cluster: state dot + word, token count, age, verdict chip right-aligned. Never let rows 1 and 3 share horizontal space.
2. The same card component serves List and Board - verify the fix does not regress List rows (they may keep a wider single-line title; if List uses a different renderer, fix Board's only and say so).
3. Check 390px narrow width: cards must keep the three-row shape without horizontal overflow; the board's own horizontal scroll for multiple columns stays as-is.

TESTS - extend mcp/sessions-ui.test.ts (the card assertions live there - editing it for the card layout it already covers is in scope): the card markup renders name, slug and meta as three sibling rows; the middle-truncation helper keeps prefix and suffix with one ellipsis and never exceeds its cap; composed page parses; narrow-layout gates stay green.

CONSTRAINTS: app-client.ts and app-styles.ts are TS TEMPLATE LITERALS - escapes DOUBLED, no backticks, no ${ }, never innerHTML, DOM via h(). Your files: those two plus mcp/sessions-ui.test.ts only.
