mcp/kernel.test.ts's tempProject() creates `.agent_memory/nodes/`, not `.agent_memory/packets/` -- irrelevant to the bug above (a red herring I chased briefly), but worth knowing if debugging that test file specifically.

Learned while delivering: M3 of the memory store: route the GRAPH sides through the StoreBackend seam, completing what M2 did for the memory indexes. The contract is docs/design/MEMORY_STORE.md (merged, guard-tested) plus mcp/store/types.ts; M2's port of catalog/by-*/FTS/vectors (merged today) is the pattern to follow - read its diff shape in mcp/kernel.ts before starting.

WHAT TO BUILD:
1. The STRUCTURAL code graph (.agent_memory/structural/{files,symbols,imports,edges}.json plus file-cache and manifest) reads and writes through openStore: files/symbols/import-and-call-edge tables on sqlite, today's files byte-compatible on json. The per-file content cache stays exactly as is if it is not already behind the seam - it is the incrementality primitive; state in your claim whether you moved it or left it.
2. The KNOWLEDGE graph (.agent_memory/graph/{entities,edges,episodes}.json) likewise: kg_entities/kg_edges/kg_episodes tables, json fallback identical to today.
3. LAZY WALKS: graph queries (the code-graph search and kg neighbourhood reads kage_context serves) must stop loading whole blobs on the sqlite backend - indexed lookups per query. On json, current behaviour stands. Golden test: the same graph query returns identical results on both backends for a fixture repo.
4. Row-level refresh: a refresh with N cache-miss files upserts only those files' rows on sqlite instead of rewriting everything; prove it with a test that counts touched rows via a store-level seam (not by timing).
5. `kage store status` gains the graph table counts (it already prints some - make sure files/symbols/edges/kg_* all appear and match a rebuild).
6. Perf smoke in your claim: measured cold rebuild and one graph query on this repo, both backends, labelled measured/machine-local.

TESTS - new file mcp/store-graph.test.ts (repo rule: new behaviour gets its own file; mcp/delegation.test.ts is off-limits). Cover: cross-backend golden equality for a structural query and a kg query; json byte-compatibility round-trip through the OLD readers; sqlite round-trips all five graph entity kinds and survives reopen; row-level upsert touches only cache-miss files' rows; rebuild idempotence extends to graph tables. Name in your claim which test fails if the change is reverted.

CONSTRAINTS: CommonJS - no import.meta, no top-level await. Zero new npm dependencies - package.json diff must be EMPTY. Your files: mcp/kernel.ts, mcp/store/**, mcp/cli.ts ONLY for the store-status table additions, docs/design/MEMORY_STORE.md + mcp/store-doc.test.ts ONLY for phase-status truth-sync, and your new test file. Do NOT touch anything under mcp/delegation/ (the W2 renderer run owns app files right now and the rest just landed), mcp/index.ts, mcp/daemon.ts. Build and test ONLY inside your own worktree - never run npm, tsc or node against /Users/kushaljain/code/Kage. If your base shows a red main has since fixed, rebase onto release-prep first.
VERIFY: npm run test --prefix mcp (967 unit + 12 dogfood green on main right now - zero failures is your bar) and npm run build --prefix mcp with no 'error TS'. Run them for real and fill in the claim fence.
