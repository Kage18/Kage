> dispatch.ts's executeRun foreground runs and supervisor.ts's superviseRun detached runs both independently hand roll …

dispatch.ts's executeRun (foreground runs) and supervisor.ts's superviseRun (detached runs) both independently hand-roll ClaimRecord assembly via buildClaim and have already drifted once before per existing repo memory — any new kernel-executed check needs to be wired into both call sites to actually apply on every run, not just one.

Learned while delivering: Add pre-claim static checks to the supervisor so a run can never reach 'ready' with code that does not compile or a client script that does not parse.

WHY (this cost four runs today): hired agents repeatedly claimed success on code that never built. Two independent agents shipped `import.meta` into a CommonJS project (TS1470). One shipped an under-escaped \\n inside the app-client template literal, which killed the ENTIRE browser script at parse time — every test passed, the app was blank. The kernel already re-executes the run's declared checks, but if the agent declares only a narrow check, nothing catches a broken build.

WHAT TO BUILD, in mcp/delegation/ (supervisor path, before the claim is accepted — find where the supervisor finishes agent work and hands off to verification; kernel-side checks live near verify.ts):

1. A new module mcp/delegation/static-checks.ts exporting `runStaticChecks(worktreeDir): StaticCheckResult`. It runs, in the RUN'S WORKTREE:
   a. `npx tsc --noEmit -p mcp/tsconfig.json` (or the project's tsconfig if mcp/ is absent) — any `error TS` output fails the check. Capture the first 5 error lines as the failure detail.
   b. The composed-page parse: import delegationAppHtml, extract the contents of the LAST <script> block that has no src attribute, write it to a temp file, and run `node --check` on it. A parse failure fails the check. Skip this step gracefully if the app renderer is not part of the changed files AND tsc passed — but ALWAYS run it when any of app-client.ts / app-html.ts / app-styles.ts changed.
2. Wire it so these run automatically as kernel-executed checks on EVERY run before the claim is judged, in addition to whatever the agent declared. They must appear in the receipt as real checks (the same VERIFIED n/n line the user reads), attributed to Kage, not to the agent — the receipt already says 'checks run by Kage, not the agent' and these belong under that banner.
3. If a static check fails, the run must NOT reach 'ready'. It goes to the state a failed check already produces, with a failure reason naming the exact compiler error or parse error. Do not invent a new state.

CONSTRAINTS:
- This project compiles to CommonJS. No `import.meta`, no top-level `await`.
- Do not shell out with a string built from unsanitized paths; use the existing spawn helpers in this repo.
- Static checks must be skippable via config for repos that are not TypeScript (add a config flag defaulting to on, and make it a no-op when no tsconfig exists) — a non-TS repo must not have every run fail.
- Keep the added time bounded: a timeout (120s) that, if exceeded, records the check as unsure rather than failed.

HOW YOU'LL KNOW IT WORKED: add tests in mcp/delegation.test.ts that (a) a worktree with a deliberate TS error fails the static check with the compiler message in the detail, (b) a worktree whose composed client script has an unbalanced quote fails the parse check, (c) a clean worktree passes both, (d) a repo with no tsconfig is a no-op pass. Then run `npm test --prefix mcp` — the whole suite (627 tests today) must stay green.
Verified by: npm test --prefix mcp, diff-size, citations
