# shell/bootstrap.js mirrors resolveCli()'s login-shell `command -v` technique as its own...

> shell/bootstrap.js mirrors resolveCli 's login shell command v technique as its own small, decoupled helper rather th…

shell/bootstrap.js mirrors resolveCli()'s login-shell `command -v` technique as its own small, decoupled helper rather than importing/sharing code with main.js — this keeps the module free of window/CLI-path knowledge (it takes `localCliExists` and an `onInstalling` callback as its only inputs from main.js), which matches the existing pattern where update.js is also a self-contained policy module with zero unit-test seam because everything it touches requires a real Electron runtime.

Learned while delivering: Close the dmg-first onboarding gap in the desktop shell (shell/main.js, shell/ only): today, launching Kage.app on a machine with no kage CLI installed dead-ends in a spawn error (resolveCli() falls back to bare 'kage' and the error is shown plainly). A user who downloads the dmg before ever running the npx install must get a working first run instead. Requirements: (1) detect the missing engine BEFORE spawning (command -v via the login shell already exists — reuse it); (2) within the shell's zero-HTML rule (no renderer code, native surfaces only), show a native dialog (Electron dialog API) that says plainly what Kage needs ('Kage runs on a local engine installed via npm') and offers [Install engine] / [Quit]: on consent, run the official install 'npx -y @kage-core/kage-graph-mcp install' as a child through the login shell so PATH/node resolution matches the user's terminal, streaming progress minimally (a native progress/indeterminate affordance or sequential dialogs — no fake progress bars), then continue the normal launch path on success; (3) if node/npx themselves are absent, say exactly that and open https://nodejs.org rather than pretending; (4) never install anything without the explicit dialog consent, never retry loops on failure — one honest error with the command the user can run themselves; (5) respect a KAGE_NO_BOOTSTRAP=1 env to suppress the whole flow. Keep main.js readable — put the flow in a small module (shell/bootstrap.js) and add it to electron-builder files. The mcp suite must stay green; document in a comment why this is verified manually (packaging) if no seam exists for unit tests. Cite files individually.
