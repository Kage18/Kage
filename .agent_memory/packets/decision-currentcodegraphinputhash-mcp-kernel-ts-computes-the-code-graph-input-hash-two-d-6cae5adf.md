# currentCodeGraphInputHash (mcp/kernel.ts) computes the code-graph input hash two differ...

> currentCodeGraphInputHash mcp/kernel.ts computes the code graph input hash two different ways depending on whether a …

currentCodeGraphInputHash (mcp/kernel.ts) computes the code-graph input hash two different ways depending on whether a structural index already exists on disk (structural-fingerprint-based when present, raw-file-hash-based when absent) -- computing this hash BEFORE triggering a rebuild and comparing it against a graph built AFTER the rebuild spuriously reads as permanently stale on a from-scratch checkout, since the rebuild creates the structural index and switches which hash function applies. The fix is to always compute the expected input hash after any local rebuild, never before.

Learned while delivering: P1a — derived state is never committed again. Today .agent_memory/indexes, code_graph, graph, structural, metrics.json (and any other refresh-generated artifact directories) are committed and churn on every refresh — they were most of the 127-conflict master merge. Change: (1) add them to the repo's gitignore via the same mechanism that already ignores runs/worktrees/daemon/room (find ensureDelegationIgnores or its kernel equivalent and extend it, plus the actual .gitignore), and remove them from git tracking with git rm -r --cached in this run's branch so the merge lands the decommit; (2) audit every reader of these artifacts (kage_context, recall, pr check graph-freshness, viewer/portal, sync) and make each one REBUILD locally when the artifact is missing rather than failing — the rebuild path exists (refresh/store rebuild); the change is tolerating absence with an automatic local rebuild and an honest one-line note; (3) kage pr check's 'graph artifacts current' gate must compare against local artifacts only and must not demand committed ones; (4) the sync workflow (the kage sync bot that produced commit 20a0a65) must stop committing derived dirs — find where it stages and restrict it to packets; (5) tests: a fresh checkout with no derived artifacts serves kage_context/recall/pr-check by rebuilding locally; refresh after this change produces zero git-visible churn outside packets. State plainly in your claim which readers you audited. Full suite green; cite files individually.
Verified by: npm test --prefix mcp, diff-size, citations, npx tsc --noEmit -p mcp/tsconfig.json, reachability
