# The app must show memory, and must not render an unmeasured metric as zero

> Until this change the Kage app showed only orchestration Room/Inbox/Runs/Board while 320 packets, the gains ledger an…

Until this change the Kage app showed only orchestration (Room/Inbox/Runs/Board) while 320 packets, the gains ledger and every health signal were visible only in the legacy viewer — the product's entire pitch was invisible inside its own app. CLAUDE.md already warns that "Kage's value is otherwise invisible, and a user who never sees it churns"; the app was the biggest instance of exactly that. mcp/delegation/memory-view.ts + the /memory routes + a fifth view fix it, reading only pre-built indexes so the whole surface costs ~2ms rather than the kernel's minutes.

Two presentation rules are enforced in code, not left to whoever edits the UI next:

1. OBSERVED and ESTIMATED are separated. Recalls served, stale memories caught and packets written are counted events and lead the hero. tokens_saved is a model (the greater of a read-vs-source and a knowledge-replay estimate), so it sits below a rule, in smaller type, with the word "estimate" attached, and is hidden entirely when zero — "~0 tokens saved" is noise, not modesty.

2. `MemoryOverview.measured` distinguishes a measured zero from an unmeasured one. Without it a fresh repo rendered "0% avg quality" and "0% evidence-backed", which reads as "your memory scored nothing" when the truth is "nothing has been measured yet". Unmeasured metrics now render "—". This is the same lesson as the v4.0.5 portal redesign (empty metrics must become unlock CTAs, never fake zeros) and it recurs because a missing number and a zero number are the same JavaScript value.
Evidence: /memory returns 320 packets in 645ms on this repo against 227s for the legacy viewer. Verified in the browser on two repos: Kage shows "320 memories written / 28 recalls served / 2,738 stale memories caught" with ~2.7M labelled an estimate; a fresh repo shows 2 packets, no estimate line, and "—" for avg quality, evidence-backed, used recently and never recalled.
Verified by: npm test — 537 pass 0 fail, exit 0 (8 memory-view tests including one asserting measured:false is what prevents rendering 0%)
