# Localhost is not a security model: guard Origin, Host and a 0600 token

> Binding to 127.0.0.1 is not a security boundary. A browser on the same machine will send a cross site POST to a local…

Binding to 127.0.0.1 is not a security boundary. A browser on the same machine will send a cross-site POST to a localhost port without needing any CORS permission, since CORS gates reading the response and not sending the request, and a DNS rebinding attack resolves an attacker hostname to loopback so the packet genuinely arrives locally. Kage daemon had eight unauthenticated POST routes, so before any run control route could exist the blast radius would have gone from memory poisoning to dispatching a coding agent with edit permissions into the user repository. The guard in mcp/delegation/guard.ts is a pure function so it is testable without a server: it refuses any request whose Host header is not loopback, which is what catches rebinding because the packet looks local but the browser thinks it is talking to another site; it refuses a foreign Origin while allowing a missing one, since curl and the CLI and the desktop shell send none; and it requires a token on every method that is not GET, HEAD or OPTIONS, compared in constant time. The token is regenerated on each daemon start and written beside the status file with mode 600, because a credential that outlives its process is one nobody is tracking. Testing note: a live rebinding attempt cannot be simulated with node fetch because Host is a forbidden header name, so that case is proven by unit test rather than by the live run.
Verified by: npm test --prefix mcp: 451 unit + 12 dogfood pass; live daemon on port 3199 refused a cross-site POST with 403, refused unauthenticated and wrong-token POSTs with 401, accepted the real token with 200, kept GET /health open, and wrote the token file with mode 600
