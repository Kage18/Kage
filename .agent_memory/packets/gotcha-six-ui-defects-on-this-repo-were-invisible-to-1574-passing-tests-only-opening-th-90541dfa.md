# Six UI defects on this repo were invisible to 1574 passing tests — only opening the app found them

> A visual sweep of every page in the portal nav found six real defects that the entire test suite passed straight thro…

A visual sweep of every page in the portal nav found six real defects that the entire test suite passed straight through: (1) seven CSS classes used by all three orchestrator pages had NO rules at all, so cards had no borders and inline spans ran together; (2) there were no element-level input/button styles, so any control without a class fell back to a white browser default on a dark theme; (3) the system map reserved a column for every EMPTY lane, wasting 40% of canvas width and pushing real content off-viewport; (4) SVG node labels neither wrap nor clip, so long names ran across neighbouring nodes; (5) the Review queue rendered its identity control ABOVE the page h1 because the container placed it before the page component; (6) a metric tile showed stale_withheld's value under stale_caught's name, overstating it ~10x. The pattern: tests assert DATA correctness and cannot see layout, cascade collisions, element defaults, or a label attached to the wrong field. Budget a screenshot pass over every route before calling a UI done, and check new CSS against the existing stylesheet for class collisions — I silently restyled the shared Overview page and StatusBadge component by reusing .metric-grid/.metric-value/.status-badge.
Evidence: All six found by screenshotting /app/{attention,work,proof,agents,overview,system-map,decisions,review,tasks} and a detail route on this repo; each fixed in commits c1402a7, 58a028b, 3d96a1e with tests where the defect was expressible as data.
Verified by: visual sweep of the running app, 2026-07-28
