# The fresh-repo honesty property holds end to end — acceptance test and how to re-run it

> The single most important acceptance scenario for Kage's honesty claims is a clean git repo with NO configured test c…

The single most important acceptance scenario for Kage's honesty claims is a clean git repo with NO configured test command. It is every new user's first hour, and it is where every honesty bug found on 2026-08-18 lived: when nothing executes, only non-executing checks run (diff-size kind "diff", citations kind "citation", reachability kind "analysis"), they all pass, and any code that folds `checks.every(c => c.result === "pass")` concludes "verified" while having proven nothing.

Verified on 2026-08-19 that all four consequences now behave honestly in that environment:
1. The receipt reads "UNVERIFIED — nothing was executed (3/3 static checks)", not VERIFIED n/n.
2. claimVerdict reports executed:false even though every check passed.
3. A goal with autonomy "merge" HOLDS the run at ready instead of auto-merging it — the gate requires claimVerdict(claim).executed, not merely all-checks-pass.
4. computeTrackRecord scores verified_first 0, so the trust metric that gates autonomy does not inflate.

HOW TO RE-RUN IT (this is the check to repeat before any release, because a single permissive fold reintroduced anywhere silently breaks all four): make a temp git repo with one committed file and no package.json; createGoal with autonomy "merge"; dispatchRun with the stub adapter attached to that goal; then assert renderClaimCard contains UNVERIFIED, claimVerdict().executed is false, readRun(...).state is still "ready" rather than "merged", and computeTrackRecord's verified_first total is 0. A working harness lives in the session scratchpad pattern — roughly 40 lines against mcp/dist.

WHY THIS BELONGS IN A RUNBOOK RATHER THAN ONLY IN UNIT TESTS: the unit tests each cover one call site, and the bug class is "someone adds a fifth place that folds checks". This scenario exercises the whole chain at once from the outside, the way a user meets it. It caught what 700+ green unit tests did not.
Evidence: Ran a fresh temp git repo (one committed file, no package.json, no test command) with a goal set to autonomy "merge" and a stub-adapter run attached. Output: receipt header "UNVERIFIED — nothing was executed (3/3 static checks)"; checks that ran were diff-size(diff), citations(citation), reachability(analysis); every-check-passed true while claimVerdict().executed was false; run state after reaching ready remained "ready" rather than "merged"; computeTrackRecord reported chore dispatched 1, verified_first 0.
Verified by: Live end-to-end run against the compiled mcp/dist on branch release-prep
