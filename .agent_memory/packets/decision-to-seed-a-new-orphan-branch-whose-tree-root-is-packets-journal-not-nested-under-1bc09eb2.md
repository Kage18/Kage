# To seed a new orphan branch whose tree root is {packets/, journal/} (not nested under ....

> To seed a new orphan branch whose tree root is {packets/, journal/} not nested under .agent memory/ without ever chec…

To seed a new orphan branch whose tree root is {packets/, journal/} (not nested under .agent_memory/) without ever checking that branch out over the code tree: use a scratch GIT_INDEX_FILE with `git --work-tree=<projectDir>/.agent_memory add packets journal`, then `write-tree` + `commit-tree` (no parent) + `git branch <name> <sha>` — never touches an existing commit, satisfying 'old paths left in code-branch history untouched'.

Learned while delivering: P2b — memory leaves the code working tree (design law 3, BELIEF_MEMORY.md storage section): introduce an OPT-IN dedicated memory branch so .agent_memory/packets and journal live on a branch (e.g. kage/memory) checked out as a hidden worktree, instead of the code branches. Requirements: (1) 'kage memory-branch migrate' performs the one-time move — creates the branch carrying packets+journal history (git subtree/filter or fresh branch seeded from current state with the old paths left in code-branch history untouched), sets up a hidden worktree (e.g. .agent_memory/.branch-worktree or an internal path the existing ignores cover), and repoints the kernel's packet/journal roots through ONE resolver function so every reader/writer follows automatically; (2) fully OPT-IN and reversible — without migration nothing changes (all tests keep passing in the default layout), and 'kage memory-branch status' reports which layout is active; (3) sync semantics: commits to the memory branch are made by the same ratify/learn flows that commit today, but on the memory branch, so code branches stop carrying memory commits entirely; kage-sync.yml gains the branch awareness; (4) merges of code branches can never conflict on memory again because memory files are not in the code tree; document the model and its tradeoffs (shared-branch contention, how two machines converge — append-only journal makes their union trivial) in the design doc's storage section; (5) tests: migrated fixture serves recall/gc/pr-check identically; un-migrated layout untouched; migration is idempotent and refuses a dirty tree with a plain message. This is the riskiest storage change yet — keep the resolver seam tiny and the migration explicit, never automatic. Suite green; cite files individually.
