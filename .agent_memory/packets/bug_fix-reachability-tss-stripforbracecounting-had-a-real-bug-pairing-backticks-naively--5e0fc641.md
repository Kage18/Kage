> reachability.ts's stripForBraceCounting had a real bug: pairing backticks naively 1st with 2nd, 3rd with 4th mis pars…

reachability.ts's stripForBraceCounting had a real bug: pairing backticks naively (1st-with-2nd, 3rd-with-4th) mis-parses a template literal that contains a nested template literal inside one of its `${...}` substitutions (e.g. `` `${cond ? `a` : `b`}` ``, found at mcp/delegation/brief.ts:144) — it silently erases real code and can desync brace-depth counting enough to prematurely close an enclosing function's scope, turning every later reference in that function into a false 'unreachable' one.

Learned while delivering: The reachability check that just landed is too noisy to trust, and it found one real bug that needs a guard. Fix both.

MEASURED FALSE-POSITIVE RATE (run findOrphans against mcp/delegation/goal.ts + mcp/delegation/contract.ts on the current tree to reproduce): 11 findings, of which 5 are orphan-export. Ground truth by grep of non-test production code:
- CLAIM_PROTOCOL_VERSION — 9 production references including a real 'import { CLAIM_PROTOCOL_VERSION }' in mcp/delegation/brief.ts:12, used at brief.ts:117. FLAGGED ANYWAY. Clear false positive.
- CLAIM_PROTOCOL_INSTRUCTIONS — imported and used by brief.ts too. False positive.
- RUN_STATES, GOAL_STATES — check each; both appear referenced.
- runTitle — the ONE true positive. See below.
An advisory check that is wrong ~4 times in 5 gets ignored, and an ignored check is worse than no check because it occupies a receipt line and implies coverage that is not there.

FIX 1 — precision. Find why an imported, called symbol is reported as unreachable. Start at the entry-point BFS and the reference scan in mcp/delegation/reachability.ts: a symbol named in an 'import { X } from' statement in a file that is itself reachable must count as a reference to X. The module's own header already admits there is no import resolution and that same-named symbols in different files are merged into one node — that approximation is the likely cause, and it is now demonstrably producing wrong answers on real code. Whatever you change, the acceptance bar is: CLAIM_PROTOCOL_VERSION, CLAIM_PROTOCOL_INSTRUCTIONS, RUN_STATES and GOAL_STATES must NOT be reported, while runTitle MUST still be reported. Put that exact expectation in a test using the real repo files.
If you cannot get precision up, say so plainly in your claim and propose removing the orphan-export rule rather than shipping a check nobody can trust — that is an acceptable outcome, not a failure.

FIX 2 — guard the real finding. runTitle in mcp/delegation/contract.ts has NO production caller: nothing imports it. The browser client carries a hand-written duplicate at mcp/delegation/app-client.ts:82 ('function runTitle(run)') whose comment says it 'mirrors runTitle in mcp/delegation/contract.ts exactly'. Two implementations of one rule, kept in sync by hand, in a renderer that is a TS template literal. I compared them across 7 inputs (short intent, 200-char intent, empty intent, multi-line, a realistic long intent, many-words, trailing colon) and they agree TODAY — so this is a drift hazard, not a live bug. Do not rewrite either implementation.
Add a test (mcp/reachability.test.ts is fine, or a new mcp/run-title.test.ts) that extracts the client's runTitle from the COMPOSED page — call delegationAppHtml, pull the function source out of the emitted script, and evaluate it with node:vm in its own context — then asserts it returns character-identical results to contract.ts's runTitle across a corpus of at least the 7 shapes above plus a few you choose. That converts a hand-kept promise into an enforced invariant.
Then decide the honest disposition of the TS export and state your reasoning: either mark it '// reachability: mirrored into the browser client by hand; the parity test is the contract' so the check stops flagging a symbol we knowingly keep, or wire the client to be generated from it. Prefer the marker — generating client code from TS is a bigger change than this task should make.

CONSTRAINTS: CommonJS — no 'import.meta' (TS1470), no top-level await. app-client.ts is a TS template literal: client-side escapes are DOUBLED, no backticks, no ${ } — but you should not need to edit it beyond possibly one comment. Do not touch mcp/delegation/goal.ts, mcp/delegation/manager-client.ts or mcp/delegation/checks.ts. Do not run kage_refresh, kage_learn or kage_pr_check.
VERIFY: 'npm run test --prefix mcp' (658 green before your change — note 'npm run test', that form is permitted where 'npm test' may be denied) and 'npm run build --prefix mcp' with no 'error TS'.
