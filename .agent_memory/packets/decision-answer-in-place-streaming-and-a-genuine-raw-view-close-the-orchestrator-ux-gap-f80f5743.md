# Answer-in-place, streaming, and a genuine raw view close the orchestrator UX gap

> Three interaction patterns adopted from studying AO, Conductor, Sculptor and Claude Code, each closing a measured gap…

Three interaction patterns adopted from studying AO, Conductor, Sculptor and Claude Code, each closing a measured gap. First, answer in place: pressing enter on a waiting agent from the board opens an answer prompt right there and delivers it to that agent, while enter on any other run opens review and the i key inspects without answering. The negative evidence is decisive — users of a competing manager abandoned it for raw tmux because replying meant attaching to a session, typing, detaching and returning, when the preview already showed everything they needed. If answering costs a context switch the orchestrator gets bypassed. Second, streaming: the manager pane now renders text and tool calls as they arrive through an onEvent callback rather than withholding everything until the run ends, because a surface that stares back blankly for twenty seconds reads as broken however good the eventual answer, and the user can keep typing while it works. Third, a genuine raw view: the review screen cycles receipt, diff, brief and raw, where raw is every transcript event unfiltered. A density control whose top setting still hides things is worse than none at all, since it teaches the reader that the tool lies about completeness. Also adopted: a waiting agent announces its question at the top of every review view, and the prompt label and hint change with the mode so the enter key never silently means something new.
