# Work is the one run surface: powers attach to the run, and collapsing the doors exposed a nobody-owns-stopped bug

> The app's Inbox/Runs/Board views were the same runs behind three doors with different powers each merge from two, ste…

The app's Inbox/Runs/Board views were the same runs behind three doors with different powers each (merge from two, steer from one, look-only from the third). They are now ONE Work view in mcp/delegation/app-html.ts + app-client.ts: a triaged list (Asks you → Needs a decision → Ready to merge → Working → Done) beside the run detail, a List⇄Board layout toggle, and the board opening the SAME #run-detail as a slide-over — so every power (answer inline, merge, reject, steer) works from every arrangement. Selection is a real model: j/k/arrows traverse in paint order (state.workOrder is rebuilt by whichever layout renders), Enter focuses the selected run's primary action (a blocked run's answer field, else the steer composer), rows are tabbable with visible focus. A gate in mcp/delegation-api.test.ts fails if v-inbox/v-runs/v-board reappear or a second run-detail element splits the power set. The collapse immediately exposed a kernel bug the split had hidden: ownership() in mcp/delegation/contract.ts mapped stopped runs to "working", so the inbox never listed them, Runs filed them under Working, and Board filed them under Lost — three surfaces, three stories about one run, and nobody owned it. stopped now maps to needs_you. The transferable lesson: when several views render the same records through different filters, their disagreements are invisible until the views share one screen — unifying redundant surfaces is a bug-finding act, not just a UX one.
Evidence: Live daemon showed the same run as Working (list) and Lost (board) in one glance after the collapse; /runs API confirmed display_state=stopped with ownership=working before the contract.ts fix.
Verified by: Commit 072a92b; regression test "a stopped run needs a human — it cannot make progress by itself"; 563/563 tests exit 0; browser walkthrough of both layouts, slide-over, and j/k/Enter on port 3111.
