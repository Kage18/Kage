# The hired-agent spawn path's own permission gap (no --allowedTools) blocks the hired ag...

> The hired agent spawn path's own permission gap no allowedTools blocks the hired agent working on THIS task from runn…

The hired-agent spawn path's own permission gap (no --allowedTools) blocks the hired agent working on THIS task from running npm test, node --test, or even git diff/status — confirmed by direct reproduction, not inference. Any future task dispatched under the old flags will hit the same wall until this fix merges.

Learned while delivering: Hired agents cannot run a single command — every dispatched agent has been working blind. Fix the spawn flags.

ROOT CAUSE (verified, not guessed): in mcp/delegation/adapters/index.ts the claude adapter spawns hired agents with '--permission-mode acceptEdits' and NO '--allowedTools' — on both spawn paths, the one-shot 'args' builder (~line 20-29) and 'claudeLiveArgs' (~line 47-58). acceptEdits auto-approves FILE EDITS only; Bash commands still require permission, and in headless '-p' mode there is no interactive prompt to answer, so every command is denied outright with 'This command requires approval'.

PROOF: two independent hired agents reported this in their claims today, unprompted and in the same words — that 'npm test', 'node --test', 'npx tsc' and even plain 'node dist/x.js' all returned 'This command requires approval' with no approval path reachable, and that only 'npm run build' happened to succeed. One of them consequently shipped a broken test path it could not observe, and Kage's own re-run caught it. Agents have been REASONING about correctness instead of OBSERVING it.

THE SAME BUG WAS ALREADY FIXED ON THE MANAGER PATH, which is why this is drift, not a design choice: mcp/delegation/manager-client.ts:59 and mcp/delegation/room-supervisor.ts:153 both pass '--allowedTools' with an explicit list, and room-supervisor.ts carries a comment saying exactly this — that spawn sites drifted and that acceptEdits covers file edits only, MCP tools need an explicit allow in headless mode. The hired-agent path never received that fix.

WHAT TO BUILD in mcp/delegation/adapters/index.ts:
1. Export a named constant (e.g. AGENT_ALLOWED_TOOLS) listing the tools a hired agent legitimately needs to do its job and verify it: Read, Write, Edit, Glob, Grep, and Bash. Add a comment stating WHY each is needed and why Bash in particular is the difference between an agent that can check its work and one that cannot.
2. Pass '--allowedTools' with that list on BOTH spawn paths — the one-shot 'args' builder and 'claudeLiveArgs'. Neither may be left behind; that asymmetry is what caused this bug. Keep '--permission-mode acceptEdits' as well.
3. Do NOT use '--dangerously-skip-permissions'. The agent works inside a disposable git worktree and the kernel re-runs every check itself, but an explicit allowlist is still the right boundary — it is auditable and it is what the manager path does.
4. Update the brief in mcp/delegation/brief.ts: it currently does not tell agents they CAN run tests. Add a short, plain line to the reporting-protocol area telling the agent to actually run the repo's tests and build before making its claim, and to state honestly in the claim when it could not.

HOW YOU'LL KNOW IT WORKED — add tests to mcp/delegation.test.ts:
(a) the one-shot args builder includes '--allowedTools' and its value contains 'Bash';
(b) claudeLiveArgs includes '--allowedTools' and its value contains 'Bash';
(c) a test asserting BOTH paths produce the SAME allowlist, so they can never drift apart again — this is the actual regression guard, and it is the point of the task;
(d) neither path contains '--dangerously-skip-permissions';
(e) renderBrief mentions running tests before claiming.
Then run 'npm test --prefix mcp' — the suite must stay green (636 tests before your change) and 'npm run build --prefix mcp' must emit no 'error TS'.

CONSTRAINTS: this project compiles to CommonJS — no 'import.meta' (TS1470), no top-level await. Do not run kage_refresh, kage_learn or kage_pr_check; those are the operator's job. Note the irony that you yourself may not be able to run tests until this fix exists — if a command is denied, say so plainly in your claim rather than guessing at results.
Verified by: npm test --prefix mcp, diff-size, npx tsc --noEmit -p mcp/tsconfig.json
