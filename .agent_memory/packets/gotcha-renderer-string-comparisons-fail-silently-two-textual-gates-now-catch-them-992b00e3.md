# Renderer string comparisons fail silently — two textual gates now catch them

> The delegation app's renderer mcp/delegation/app html.ts is one big TypeScript template literal with hand written cli…

The delegation app's renderer (mcp/delegation/app-html.ts) is one big TypeScript template literal with hand-written client JS and CSS, so TypeScript checks none of it. Two classes of bug there fail completely silently and shipped in the same session: (1) a string comparison against vocabulary the kernel never emits — the projects rail filtered on `r.ownership === "human"` when Ownership is `working | needs_you | done`, so the "needs you" badge could never appear; (2) a `var(--x)` referencing an undefined custom property — `--warn` and `--bad` (the palette calls them `--amber` and `--crimson`), so the badge rendered as plain text with no pill and the close × never turned red. Neither produces an error anywhere; the branch just never fires and the declaration is just dropped. Both were found by LOOKING AT A SCREENSHOT, not by tests. Two gates in mcp/delegation-api.test.ts now cover them: one regex-scans the HTML for `ownership ===`/`display_state ===` comparisons and asserts each compared value is in the real union — importing RUN_STATES from contract.ts rather than hand-copying it, because a hand-copied list in the test carries exactly the defect it is guarding against (it did: it flagged "draft" as bogus on its first run, when "draft" is the first RunState); the other asserts every `var(--x)` used in the stylesheet is defined in it. Both gates were mutation-tested — reintroduce the bug into dist and they fail with the right message. Each gate also asserts it found a minimum number of matches, which caught the CSS gate itself being broken (its slice found nothing, and it would otherwise have passed vacuously forever).
Evidence: Both bugs were visible in an Electron screenshot (badge missing entirely, then rendering as plain text instead of a pill) while all 508 tests passed. After adding the gates: mutating dist/delegation/app-html.js to reintroduce `ownership === "human"` fails with 'the renderer compares ownership against "human", which the kernel never emits'; mutating `var(--amber)` to `var(--warn)` fails with 'these custom properties are used but never defined: --warn'. Restoring both returns the suite to green.
Verified by: npm test in mcp/ — 528 pass, 0 fail, real exit code 0 (checked unmasked, not through a pipe)
