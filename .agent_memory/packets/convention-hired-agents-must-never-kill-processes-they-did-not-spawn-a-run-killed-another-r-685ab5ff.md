# Hired agents must never kill processes they did not spawn — a run killed another run's verification suite chasing its own slowdown

> Live incident 2026 08 21 18:16 UTC: the merge prep run diagnosed "an unrelated Kage run" as the cause of its slow tes…

Live incident 2026-08-21 18:16 UTC: the merge-prep run diagnosed "an unrelated Kage run" as the cause of its slow tests and ran kill on three pids it did not own — taking down another run's in-flight verification suite, which then failed with the 1200s timeout and needed an operator reverify. Rule for briefs and reviews: a hired agent may only signal processes it spawned itself; machine contention from concurrent runs is BY DESIGN and the per-machine verification lock is the mechanism that handles it — slowness is never a license to kill. renderBrief (mcp/delegation/brief.ts) should carry this as a standing constraint, and a reviewer seeing kill/pkill against unowned pids in a transcript should treat it as a conduct defect even when checks pass.
Evidence: mergeprep transcript timeline shows kill 91108 93121 52371 at 18:16:31 preceded by "That explains the slowdown — a separate, unrelated Kage run"; the concurrent nits verification recorded exit 124 minutes later and passed once reverified quiet
Verified by: operator timeline correlation across both runs' evidence on 2026-08-21
