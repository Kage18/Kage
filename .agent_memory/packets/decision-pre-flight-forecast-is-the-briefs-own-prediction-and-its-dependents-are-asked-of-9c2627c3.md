# Pre-flight forecast is the brief's own prediction, and its dependents are asked of memory-cited paths

> GET /preflight mcp/delegation/preflight.ts, served from mcp/delegation/api.ts renders risk before any diff exists: as…

GET /preflight (mcp/delegation/preflight.ts, served from mcp/delegation/api.ts) renders risk before any diff exists: as the user types an intent, the composer shows "lands near X, Y +N · M files depend on that area · K memories will ride in the brief", labeled FORECAST. Two design rules matter for anyone extending it. First, the forecast is compileBrief's own touch prediction — never a second heuristic — so it can never disagree with the brief that dispatch actually compiles. Second, the dependents question must be asked of the MEMORY-CITED paths, not the full predicted touch set: queryCodeGraph expands touches with every file matching the intent's terms, which includes the dependents themselves, and blastRadiusFor then excludes them as intra-change — the forecast undercounts exactly the risk it exists to show (dependents read 0 in the first test run; memory-cited basis reads the true count). Graph touches are the blast basis only when memory is silent. Also: hand-seeding .agent_memory/structural/imports.json in tests does not survive — recall() keeps the structural index fresh and overwrites it — so tests must create real files with real imports and let the indexer produce edges. /preflight rides the daemon's self-warm because the first recall pays a ~1.5s lazy index load; warmed it answers in ~0.26s, inside the 450ms-debounced type-ahead budget.
Evidence: First test run measured dependents 0 with the full-touches basis (graph pulled a.ts/b.ts into touches); memory-cited basis measured 2. Live repo: "fix the daemon index watcher loop" forecast 32 dependents in the Room composer and recalled the hours-old index-loop packet as top memory.
Verified by: Commit 0f99e3e; 565/565 tests exit 0; browser verification of composer + modal forecasts; endpoint latency measured 1.48s cold / 0.26s warmed on port 3111.
