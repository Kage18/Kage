# The concurrency cap had two independent, compounding bugs: (a) checked AFTER the agent ...

> The concurrency cap had two independent, compounding bugs: a checked AFTER the agent child was already spawned inside…

The concurrency cap had two independent, compounding bugs: (a) checked AFTER the agent child was already spawned (inside the dispatched->running transitionRun call), so a full slate killed the supervisor and orphaned a live working agent; (b) even after fixing the ordering, the checking run's own just-written 'dispatched' record counted against its own admission, turning a configured cap of N into an effective N-1.

Learned while delivering: Budgets become a circuit breaker, not a thermostat: raise the default, stop stopping on minutes, and catch actual stalls instead.

THE EVIDENCE, from running this product all day yesterday: the kernel stopped five runs on budget. All five were legitimate work; all five later merged clean ($5.22, $4.85, $8.62, $25.47, $6.04 against the $2.00 cap). Zero runaways caught, five good runs interrupted. And the cap does not even cap: enforcement overshot 2.6x on one run and 12.7x on another, so the money was already spent when the stop landed. The minutes cap was worse - it stopped nothing bad, and (before yesterday's fix) counted idle time. The hazard budgets actually exist for is an agent LOOPING - retrying the same failing command, thrashing with no progress - unattended at max_concurrent 3. Cost is a bad proxy for that; catch the loop itself.

WHAT TO BUILD:
1. DEFAULT_RUN_BUDGETS (mcp/delegation/contract.ts, currently { usd: 2, minutes: 30, diff_lines: 400 }): usd 2 -> 50. It is a circuit breaker for pathology, not a per-task allowance. diff_lines unchanged.
2. Minutes stops being a stopper ANYWHERE. checkRunBudget must stop only on usd. Keep measuring and displaying minutes everywhere it is shown today (the meter itself - runningMinutesElapsed / workingMinutes - stays exactly as is; it was fixed yesterday to count work, not waiting). Displays that render minutes-over-cap as an alarm (mcp/delegation/app-client.ts around line 1566 renders a 'hot' over-budget row; check report.ts and tui/app.ts for the same) become informational: show the number, drop the alarm. Purge every stop note and resume message that advises raising a minutes cap to recover a stop - that path no longer exists. `kage resume-run --budget-minutes` may remain as a harmless raise but nothing demands it.
3. A STALL DETECTOR in mcp/delegation/supervisor.ts - the thing budgets were standing in for. The supervisor already parses every stream event. Track, per agent turn: the commands it ran and their exit codes, and whether the worktree's diff changed (a cheap `git -C <worktree> diff --stat` hash between turns is acceptable; do not shell out more than once per turn). Trigger when EITHER (a) the same command fails with the same exit code 3 consecutive times, or (b) 6 consecutive turns produce zero worktree change AND zero new file reads is NOT required - just zero diff change. On trigger: stop the run (state 'stopped') with a note that leads with the word 'stalled:' and names the exact evidence ('stalled: `npm test` failed with exit 1 on 3 consecutive turns'). Constants named and documented at the top of the detector, conservative on purpose. A long single turn must never trip it. Varied exploration (different commands, reads, no edits yet) must never trip it - condition (b) needs SIX turns precisely so research phases survive.
4. A stall-stopped run resumes WITHOUT budget flags: resumeStoppedRun (mcp/delegation/recovery.ts) currently refuses when no cap is crossed and no raise offered. When the run's last stop note begins 'stalled:', resume with no flags - the resume steer message should tell the agent it appeared stalled and quote the evidence, so it changes approach instead of resuming the loop.
5. The kernel stop note for a usd stop keeps naming `kage resume-run <run-id> --budget-usd <n>` as it does today.

TESTS - new file mcp/stall-detector.test.ts for the detector (repo rule: new behaviour gets its own file; mcp/delegation.test.ts is off-limits). mcp/resume-budgets.test.ts and mcp/budget-config.test.ts contain assertions that encode the minutes-stopping behaviour this run deliberately removes - UPDATE those specific assertions (this is sanctioned; the behaviour change is the point), but keep the meter tests (runningMinutesElapsed) untouched since the meter does not change.
