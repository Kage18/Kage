# Blast radius from the prebuilt imports index — and the two-writer claim drift it exposed

> Runs awaiting a merge decision now carry a blast radius "5 files depend on this" computed by mcp/delegation/blast rad…

Runs awaiting a merge decision now carry a blast radius ("5 files depend on this") computed by mcp/delegation/blast-radius.ts from .agent_memory/structural/imports.json — the prebuilt index (1ms load, cached by mtime, from_path→to_path edges; to_path null means external package). It must NEVER call kernel analysis functions: kageRisk measured 39s on this repo and blast serves inside GET /runs. Same law as memory-view.ts: request paths read prebuilt indexes only. Honesty rule: null (chip absent) when the index or the claim's paths are missing — "0 dependents" invented from a missing index reassures falsely; zero is only shown when the index answered.

Building it exposed the more important lesson: ClaimRecord was assembled by hand in TWO places — dispatch.ts (foreground runs) and supervisor.ts (detached runs, the path real users actually hit). Adding diff.paths to dispatch.ts changed nothing live, because supervisor.ts's copy silently lacked the field while every test of the foreground path passed. The claim's changed paths were being measured (DiffStats.paths in verify.ts) and thrown away at write time. Fix: ONE buildClaim() in contract.ts, both callers use it, and a gate in delegation.test.ts fails if either file ever matches a hand-rolled `schema_version: RUN_SCHEMA_VERSION, run_id` literal again. When a record has two writers, a schema change WILL reach only one of them, and it will be the tested one, not the real one.

Verified end to end with a real detached claude run in a repo where mod2-mod6 import mod1: editing mod1.js produced blast {dependents: 5, sample: [mod2.js, mod3.js, mod4.js]} through the API and an amber "5 files depend on this" chip in the run header.
Evidence: Live: dispatched a claude run against mod1.js in a 12-module repo with 5 importers; GET /runs returned blast {"dependents":5,"sample":["mod2.js","mod3.js","mod4.js"]} and the UI showed the amber chip. The drift was observed directly: after patching dispatch.ts only, a real detached run's claim.json still had diff {files,lines} with no paths.
Verified by: npm test — 558 pass 0 fail exit 0, including 6 blast-radius tests (missing index → null; torn index → null; mtime cache refresh) and the buildClaim-only gate
