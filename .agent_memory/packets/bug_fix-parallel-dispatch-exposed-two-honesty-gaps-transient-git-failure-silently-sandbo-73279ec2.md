# Parallel dispatch exposed two honesty gaps: transient git failure silently sandboxes a run, and a blocked run with a dead supervisor is unstoppable and unrejectable

> The first live orchestrated wave two runs dispatched simultaneously by the Room manager, 2026 08 18 surfaced two kern…

The first live orchestrated wave (two runs dispatched simultaneously by the Room manager, 2026-08-18) surfaced two kernel bugs that only appear under real parallelism. (1) SILENT SANDBOXING: isGitRepo and hasCommits in mcp/delegation/git.ts are `git(...).ok` — false on ANY git failure, including transient index.lock contention while two concurrent `git worktree add` calls run. superviseRun's workspace choice (`isGitRepo && hasCommits ? createWorktree : runWorkDir`) therefore classified a healthy repo as not-a-repo and handed the agent an EMPTY sandbox directory with no code. The agent behaved perfectly — it refused to work and reported "no isolated git worktree; shared checkout unsafe with 2 concurrent runs" — but the kernel had already lied to it. Same conflation shape as stdin.write()'s return value (backpressure vs failure) and as any boolean that merges "said no" with "could not ask": third instance in one day. Fix direction: distinguish command-failed from command-answered-no (retry transient git failures; treat a .git that exists on disk while git commands fail as an ERROR, never as a sandbox), and retry createWorktree on lock contention. (2) BLOCKED ZOMBIE: a blocked run whose supervisor has died cannot be stopped (stop honestly reports "no live supervisor — nothing to stop" and leaves state blocked) and cannot be rejected (the reject gate refuses blocked states because "an agent is waiting on you"). Nothing is waiting, so the run is permanently stuck. blocked is deliberately excluded from the reaper's staleness check, which is right for a live block and wrong for a dead one. Fix direction: stop on a blocked run with no live supervisor must persist reality (transition to stopped), which makes reject legal again.
Evidence: Run supervisor-pre-claim-static-checks-mcp-d-260818-55fb: task.json worktree null, no branch created, .agent_memory/runs/<id>/work empty, agent blocked with the quoted question; a sibling run dispatched moments earlier got a proper worktree. Stop returned ok with "no live supervisor — nothing to stop" and state stayed blocked; reject returned ok:false.
Verified by: Live orchestration on 2026-08-18 against the merged Goals build (603/603 green); worktree list, task record, and empty work dir inspected directly.
