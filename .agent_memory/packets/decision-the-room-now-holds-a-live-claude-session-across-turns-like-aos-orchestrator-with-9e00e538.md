# The room now holds a live claude session across turns, like AO's orchestrator — with a verified-honest fallback

> Driving AO's real orchestrator showed its "manager" is literally a held, live instance of the underlying agent CLI — …

Driving AO's real orchestrator showed its "manager" is literally a held, live instance of the underlying agent CLI — same mechanism our worker supervisor already used per run, just never applied to the room/manager. Before building on that, empirically verified (not assumed) that a claude process spawned with --input-format stream-json, given a second stdin user frame after the first turn's "result" event WITHOUT closing stdin in between, answers with real memory of turn one — proven with a standalone probe script (remembered a codeword across two separate stdin writes to the same child process). Built mcp/delegation/room-supervisor.ts on that proof: superviseRoom(projectDir) spawns ONE claude --input-format/--output-format stream-json child, held open for the room's whole life (not per-message), with a control socket (roomSocketPath, same bounded sha256-hash-in-tmpdir pattern as the worker's socketPath) that streams each turn's progress back as newline-delimited JSON and ends the connection on "final" — the child's stdin is never closed between turns, so native model context persists exactly as verified. Session id is captured via sessionIdFrom and written to room/session.json so a killed/restarted room supervisor can --resume instead of starting cold. Wired into mcp/delegation/api.ts's resolveRoomReply: only claude is tried live (isAgentInstalled("claude") gate) — codex and gemini have real --resume/session-id support (verified via --help) but no stream-json STDIN protocol, so conflating "has an adapter" with "provably holds a session live" would repeat the exact false-confidence bug fixed earlier this session in supervisor.ts. Any failure at any step (claude not installed, spawn fails, socket unreachable after an 8s startup wait) falls through to the original askManager one-shot-with-8-turn-replayed-history path, unchanged. CRITICAL test-seam bug caught before merging: resolveRoomReply's first version tried the live path unconditionally, so on any machine with claude actually on PATH (this one), every EXISTING room test — which only overrides askManagerFn, expecting that alone to prevent touching a real CLI — would have spawned a real detached supervisor process instead of calling its injected fake. Fixed by gating the live attempt on `isProduction = !ctx.askManagerFn`: setting askManagerFn now means "a test is driving this, touch nothing real," full stop. Live-verified end to end outside the test suite: two real messages through the actual API, second one asking "what was the codeword" — answered correctly, AND the room supervisor's recorded pid was IDENTICAL before and after (proving one held process served both turns, not two separate spawns which would have looked identical from the reply content alone).
Evidence: 26 fast deterministic tests (room-supervisor.test.ts + delegation-api.test.ts additions), including a named regression test asserting askManagerFn alone resolves in <2s with no room/supervisor.json ever written. Live probe script proved cross-turn context retention before any production code was written. Live API verification: identical supervisor pid (36952) across two real turns, second turn correctly recalled a codeword only stated in turn one, room/session.json captured the real claude session id.
Verified by: npm test --prefix mcp → 483 unit + 12 dogfood pass; standalone probe script; live curl + browser verification against the real daemon with real claude auth
