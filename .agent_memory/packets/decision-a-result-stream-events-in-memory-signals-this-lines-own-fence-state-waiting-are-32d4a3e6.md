# A `result` stream event's in-memory signals (this line's own fence, state.waiting) are ...

> A result stream event's in memory signals this line's own fence, state.waiting are not the sole authority for whether…

A `result` stream event's in-memory signals (this line's own fence, state.waiting) are not the sole authority for whether to end a live child's stdin — the persisted run state must be consulted too, because a stray/duplicate result line (e.g. one triggered by a control-plane write like interrupt that a naive/scripted agent stdin-consumer misinterprets as an ordinary conversational turn) can arrive after the run is already correctly blocked, and ending stdin there would sever an answerable session out from under a later tell.

Learned while delivering: THE INTERACTION SUBSTRATE (run 1 of 3, backend only — a parallel run owns pty work and a later run owns all UI; to avoid merge conflicts DO NOT touch room-pty.ts, app-client.ts, app-html.ts, app-styles.ts). Build full Conductor-parity interaction plumbing in the kernel and API. PART A, steer queue with per-message truth: today steer.jsonl lines are bare {message} appended unconditionally, so queued-vs-delivered cannot be answered. Give each steer a record {id (short random), message, at, status: queued|delivered, delivered_at?}: steerRun (mcp/delegation/steer.ts) writes status queued and flips to delivered (atomic temp+rename rewrite of the file, matching task.json crash-safety) when live-socket delivery succeeds; superviseRun (mcp/delegation/supervisor.ts) marks a steer delivered at the moment it injects it (both the held-socket path and the reattach-resume path — the resume path currently redelivers only the newest stored steer; upgrade it to deliver ALL queued steers in order, oldest first, now that delivery is tracked). Keep readSteers in mcp/delegation/dispatch.ts returning plain messages for brief re-rendering (compat), add readSteerRecords beside it. Kernel queue mutations in steer.ts: editQueuedSteer(projectDir, runId, steerId, message), deleteQueuedSteer(projectDir, runId, steerId), reorderQueuedSteers(projectDir, runId, orderedIds) — each refuses (returns ok:false with a reason) for delivered records; delivered history is immutable. PART B, plan review as a typed object: extend the reporting protocol in mcp/delegation/contract.ts with a third fence, kage-plan: {plan: string, question?: string} — parseReportFence gains kind plan (plan required non-empty; degrade to null like the others); CLAIM_PROTOCOL_INSTRUCTIONS documents when to emit it (before large or risky changes, propose the plan and wait for approval). superviseRun on a plan fence: transition blocked with waiting_on {needs: plan approval, detail: <the plan text>} — an explicit tell (the approval or revision) resumes through the existing blocked machinery; never auto-approve. PART C, true interrupt: POST /runs/:id/interrupt in mcp/delegation/api.ts — sendControl interrupt to the live supervisor socket (mcp/delegation/control.ts has the frame), honest 503 {error: no live supervisor} when isRunLive is false; the session stays alive. PART D, queue API: GET /runs/:id/steers returns the records; POST /runs/:id/steers with {op: edit|delete|reorder, id?, message?, order?} maps to the kernel mutations, guarded like every mutation. Tests for every part in mcp/delegation.test.ts and mcp/delegation-api.test.ts using existing seams (part-1/part-2 supervisor seams, scripted spawnLive stub, real sockets, startApi harness): queue lifecycle queued→delivered with immutability refusals; reattach delivers ALL queued steers oldest-first and marks them; plan fence parses and lands blocked-with-plan and resumes on tell; interrupt route 503s honestly and delivers on a live socket; existing steer delivery-vocabulary tests keep passing. Success = npm test fully green.
