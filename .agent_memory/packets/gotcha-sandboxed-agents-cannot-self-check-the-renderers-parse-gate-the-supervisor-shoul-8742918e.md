# Sandboxed agents cannot self-check the renderer's parse gate — the supervisor should run cheap static checks before accepting a claim

> Two consecutive delegated runs on mcp/delegation/app client.ts failed verification on defects the agent could not pos…

Two consecutive delegated runs on mcp/delegation/app-client.ts failed verification on defects the agent could not possibly catch itself: run 1 tripped the innerHTML containment gate with its own comment prose ("No innerHTML, no regex" — second occurrence of the gate-vs-prose collision; the orphan-class gate hit the same shape earlier and answers it by stripping comments), and run 2 shipped a single under-escaped split("\n\n") whose single backslashes compile to a REAL newline inside the composed client string, killing the script at parse time — the exact gotcha the file header documents. Root cause of the failure LOOP, not just the failures: run agents have no execution rights in their sandbox, so they cannot run node --check on the composed page — the one check this file's conventions demand — and each miss costs a full dispatch-verify-reject-redispatch cycle (~$1.5 and ~6 minutes each). Operator recipe that breaks the loop: build the failed worktree's dist, compose the page via delegationAppHtml, write the script to a file, node --check it for the exact line, then redispatch quoting the defective line and its exact correction. Product affordance worth dispatching: the supervisor (which CAN execute) should run cheap static pre-claim checks (node --check on the composed client when app-client/app-html/app-styles changed) and feed a failure back into the still-live agent session for one self-repair round before verification — converting a full failed-run cycle into an in-run retry.
Evidence: Run fix-three-room-chat-rendering-defects-260817-7831: innerHTML gate failed on the agent's own comment, zero real usages. Run land-the-room-chat-rendering-fix-260817-13cb: parse gate failed; node --check on the composed script pinpointed line 448 split with single backslashes. Both rejected with reasons; third dispatch carries the quoted correction.
Verified by: Kernel evidence files under .agent_memory/runs/ for both runs; operator node --check reproduction.
