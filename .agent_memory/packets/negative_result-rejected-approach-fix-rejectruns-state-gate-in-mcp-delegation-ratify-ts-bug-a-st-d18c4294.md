# Rejected approach: Fix rejectRun's state gate in mcp/delegation/ratify.ts. Bug: a stopped

> A delegated attempt at "Fix rejectRun's state gate in mcp/delegation/ratify.ts. Bug: a stopped run cannot be rejected…

A delegated attempt at "Fix rejectRun's state gate in mcp/delegation/ratify.ts. Bug: a stopped run cannot be rejected — the gate allows only 'ready' and 'failed', and refuses with 'Run X is stopped — stop it before rejecting', which is nonsense for an already-stopped run. Every surface promises rejection there: contract.ts decisionText says 'Stopped — resume or reject', and the app shows a Reject button on any non-merged/non-rejected run. Fix: allow reject from ready, failed, stopped, and dropped (none has a live agent process). Keep refusing draft, briefed, dispatched, running, verifying, and blocked — blocked has a LIVE agent waiting, so stopping first is genuinely required — and make the refusal message name the actual state and the correct next step instead of always saying 'stop it'. Verify contract.ts's transition table permits stopped→rejected and dropped→rejected; adjust it minimally if it does not. Add regression tests in mcp/delegation.test.ts: (1) a stopped run rejects successfully and captures the rejection memory; (2) a running run still refuses with a message naming its state. Do not change any other reject behavior. Success = npm test fully green." was rejected.

Reason: Not a code failure: the implementation is verified good (operator re-ran kernel verifyRun after installing worktree deps: 3/3 pass, npm test exit 0, evidence on disk). The run record could not honestly reach ready because the repo config lacked a setup command at dispatch time, and the CLI-dispatch supervisor had exited, so no product path could re-verify. Redispatched on the standard detached path; the verified branch kage/fix-rejectrun-s-state-gate-in-mcp-delega-260817-fb8b holds the working implementation.

Claimed: rejectRun now allows reject from ready/failed/stopped/dropped (a dropped run is reaped to failed first, then rejected), still refuses draft/briefed/dispatched/running/verifying/blocked, and the refusal message names the actual state instead of always saying 'stop it'; contract.ts's LEGAL_TRANSITIONS gained stopped→rejected (ready→rejected and failed→rejected already existed), and two regression tests were added to mcp/delegation.test.ts covering a stopped run rejecting successfully (with a captured negative_result packet) and a running run still refusing with a state-naming message.
Branch kept for inspection: kage/fix-rejectrun-s-state-gate-in-mcp-delega-260817-fb8b
