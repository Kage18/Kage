# Testing-infrastructure gotchas found via dogfooding and fast test fixtures

**Confidence:** provisional — each gotcha is a real, evidenced incident, but the cluster is four independent situational observations rather than one settled domain, and the `vercel/ai` dogfood gaps are documented as found, not confirmed fixed.

Several unrelated, situational gotchas surfaced from running Kage against real-world repositories and from writing fast in-process test fixtures, and they are grouped here because each is a narrow, reusable technique rather than a standing architectural fact. Dogfooding Kage against `vercel/ai` (a large, real OSS monorepo) surfaced three product gaps at once: `kage init`/`recall` at the repo root failed on a broken symlink (`README.md` pointed to a target whose path contained a newline); running `kage pr check` inside a package subdirectory (`packages/ai`) could generate root-relative changed paths and then validate them against the subdirectory project, causing the tool to mark its own just-written packet stale; and a package-level `kage refresh` indexed generated build output (`packages/ai/dist`) after a type-check step produced it, meaning ignored/generated artifacts need stronger exclusion in package-scoped projects. Separately, when actually checking a real PR (`vercel/ai` #15154) against upstream CI, a red test job turned out to be an unrelated timeout in a different package's codemod test (15000ms timeout on Node 20) rather than anything caused by the PR's own diff — a reminder to read which specific package/test failed before assuming a red CI job implicates the change under review. On the test-writing side, two Node.js-specific technique gotchas were learned while building newer features: comparing git's own commit-date output (`%cI`/`%ct`, second-precision) against Node's `new Date().toISOString()` (millisecond-precision) is a genuine race at test-fixture speed, since two fast git subprocess calls back-to-back can land in the same wall-clock second — the fix was to avoid timestamp comparison entirely and use a reflog-entry-count approach instead; and Node's global `fetch()` (built on undici) silently drops or overwrites an explicit `host` header, so it cannot be used to exercise Host-header-based security guards (DNS-rebinding protection, LAN allowlisting) against a real socket in tests — `node:http`'s `request()` must be used instead, since it respects an explicit Host header passed in the headers object.

## Contradictions / open questions

- None found in the cited evidence directly conflicting with each other — these are four independent, situational observations. However, the `vercel/ai` dogfood packet reads as a list of discovered product gaps (symlink handling, subdirectory path validation, ignored-artifact exclusion) rather than a confirmed fix; this cluster's evidence does not show whether those three gaps were subsequently closed in Kage's own code, only that they were identified and evidenced against a real repo.
- The two Node.js technique gotchas (git-timestamp race, undici Host-header drop) were captured as incidental learnings inside packets whose main subject was a much larger, unrelated feature (a UI render-flicker fix and a LAN-pairing security feature respectively) — they are included here on their own merit as durable testing techniques, not as claims about the state of those larger features.
